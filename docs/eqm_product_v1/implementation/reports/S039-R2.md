Purpose and exact behavior changed:
The pure engine now evaluates comparison eligibility against the exact expected
occurrence set of the selected graph scenario rather than a submitted
participant list. Duplicate, missing and extra occurrences are ineligible;
repeated same-target actors stay distinct because each occurrence is keyed by
its own `OccurrenceId`; a covered occurrence with an absent context or subject
is incomplete and a mismatched shared context is ineligible.

The application boundary derives the shared comparison context from the
immutable prepared graph: the contract digest is the graph's own frozen
`canonicalize_contract_v2` projection (a caller-selected contract digest is no
longer accepted), and the scenario/policy/selected-profile definitions must be
exact graph members. The checked wire comparison context must equal that
independently derived identity, so a well-formed self-selected context or rule
substitution is rejected. Expected coverage is the selected scenario's exact
occurrence set. Participants are constructed only after the existing
bytes-first `match_subjects` succeeds against independently resolved authority,
and the matched result must cover exactly the scenario occurrences. A new
immutable `CheckedComparisonOutcome` retains the matched `SubjectManifest`
(occurrence/kind/configuration/content authority) and the separate
`SubjectManifestDigest`. No engine structural input can substitute a public
digest for matching proof, and eligibility never promotes to conformance or
trust.

Spec/API/schema/DB/authority impact:
Additive engine/application APIs. `shared_comparison_context` drops the
caller-supplied contract digest and derives it from the graph;
`checked_comparison_eligibility` is replaced by `evaluate_checked_comparison`.
No schema byte, wire member, v1 byte or dependency changed; no
domain/engine serialization back-edge was added. `cargo xtask schemas check`
confirms committed schemas unchanged.
