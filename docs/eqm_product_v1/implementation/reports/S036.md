## Scope

DEV-009 requires participation/applicability to be evaluated for an exact
requirement/participant/profile coordinate while true, false and unknown stay
distinct, so no single pre-fanout conclusion is applied to every target.

## Representation

`crates/eqm_engine/src/applicability.rs` adds:

- `evaluate_participation(rules, requirement, target, context)`, which finds the
  participation rule whose exact requirement and target match the requested
  coordinate and returns its typed `TruthValue`.
- An absent matching rule returns `TruthValue::Unknown`, which is
  non-authorizing; it is never an implicit global inclusion.
- The existing `ApplicabilityContext` already yields `Unknown` for a missing or
  explicitly unknown required profile dimension, so true/false/unknown remain
  distinct end to end. No global drop or waiver is synthesized.

`crates/eqm_engine/src/lib.rs` re-exports the new function.

## Tests added

`crates/eqm_engine/tests/participation.rs`:
- `participation_is_true_false_and_unknown_per_exact_coordinate`
- `unspecified_requirement_target_and_rule_stay_unknown`
- `distinct_participants_evaluate_independently`

The first covers the required matrix: the same requirement is `True` for the
edge target with the selected value, `False` for an explicit exclusion, and
`Unknown` for a missing profile value.
