## Scope

DEV-009 requires every repaired raw/semantic/nested-source/runner/lineage axis
to have a complete control and literal oracle in its real owning crate, not only
a declarative vector inventory. S027 consolidates those axes into one shared,
deterministic corpus with literal golden identities.

## Representation

`crates/eqm_test_support/src/provenance.rs` (new) is the single shared source for
the protocol, lineage and record-history axes:

- `standard_evidence_record()` builds the exact standard evidence DTO from the
  shared `eqm_protocol` constructors; `STANDARD_EVIDENCE_SEMANTIC_BYTES` and
  `STANDARD_EVIDENCE_SEMANTIC_DIGEST` are reviewed literal constants.
- `EvidenceAxis` enumerates every bound semantic member (kind, each subject
  axis, target, unit, requirement, facet, the four component digests, profile
  values, observation instant and payload kind); `mutate_axis` changes exactly
  one.
- `record_history_vectors()` returns explicit ordered definition histories with
  their declared accept/future/duplicate/missing/cycle outcomes.

Owning tests execute the corpus against the production boundaries:

- `crates/eqm_protocol/tests/provenance_corpus.rs`: parses the exact bytes
  through `CheckedEvidenceResultV2`, asserts the literal semantic bytes/digest,
  recomputes the raw identity under its own domain, proves determinism, proves
  formatting-only variants preserve the semantic identity while moving the raw
  identity, proves every bound axis moves the semantic identity, and proves
  domain separation from `SemanticEvidenceDigest`/`ContractDigest`.
- `crates/eqm_domain/tests/provenance_corpus.rs`: executes every record-history
  vector against `validate_records` and keeps the self/duplicate constructor
  controls.
- `crates/eqm_manifest/tests/provenance_corpus.rs`: loads the checked-in three
  target fixture through the real loader and asserts the android binding,
  evidence-specification and web target-configuration identities are
  deterministic across repeated loads, that a formatting-only authored change
  preserves them, and that a semantic binding or target change moves only the
  affected component identity.

The existing owning `eqm_manifest` component tests (`binding_v2`,
`evidence_spec_v2`, `contract_v2`, `policy_v2`, `target_v2`) remain the separate
literal controls for those projections; this step ties the protocol, lineage and
record-history axes into the same corpus.
