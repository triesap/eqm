Purpose and exact behavior changed:
The authored scenario is now projected independently under `eqm:v2:scenario`
(`ScenarioDigest`) over `id`, `revision`, `participants`, `dependencies` and
extensions; the complete v2 graph identity reuses that projection. A new
`ComparisonContextInputV2` domain carrier retains the shared comparison axes, and
`eqm:v2:comparison-context` (`ComparisonContextDigest`) projects exactly the four
semantic members `contract_digest`, `scenario_digest`, `profiles`,
`comparison_rule_digest`; the wire/schema root adds only the exact schema marker.
`profiles` reuses the approved selected-profile definition/value projection
(never a profile-ID-only list or the whole policy). `comparison_rule_digest` is an
explicitly supplied structural SHA reference: no rule format/domain/default and no
policy-digest substitution was invented. Exact participant build/source/artifact
assignments never enter the shared identity, so distinct subjects can share one
comparison context while remaining distinct. v1 equivalence behavior is untouched
and identity confers no subject validity or trust.

Spec/API/schema/DB/authority impact: additive domain digests/carrier, a new
generated v2 protocol schema, and no v1 or dependency change.
