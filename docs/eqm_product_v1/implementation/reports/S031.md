## Scope

DEV-009 allocates an additive version-2 authored workspace family that carries
the source-component table and explicit target `role`, `source_components` and
`depends_on` references. There is no implicit v1/v2 conversion and the v1
schema, reader and oracles stay frozen.

## Representation

- `crates/eqm_manifest/src/dto/v2.rs` (new) defines strict `WorkspaceV2Dto`,
  `TargetV2Dto` and `SourceComponentV2Dto` with `deny_unknown_fields`, all v1
  shared authored fields, and the new role/source/dependency members.
- `crates/eqm_manifest/src/config.rs` probes the declared schema URI and
  dispatches on its explicit version. A v2 document is decoded by the v2 reader;
  a v1 document by the v1 reader; a wrong kind or unsupported version still
  fails. `WorkspaceConfig` retains the v2 document and exposes it through
  `workspace_v2()`.
- `crates/eqm_manifest/src/loader.rs` builds v2 targets (role, source-component
  and target-dependency references) and the source-component table through the
  real loader, keeping the portable root-collision check. The v1 path is
  unchanged.
- `crates/eqm_manifest/src/bin/generate_manifest_schemas.rs` emits the
  version-qualified schema `$id` and a v2 workspace schema; `crates/eqm_manifest/...`
  and `tools/xtask` route generation for both versions. `schemas/v2/manifest/workspace.schema.json`
  is generated, not hand-written.
- The CLI test that asserted a v2 workspace URI must fail is corrected: v2 is an
  explicit supported workspace family; v3 and wrong-kind URIs still fail. The v2
  lock URI remains unsupported.
