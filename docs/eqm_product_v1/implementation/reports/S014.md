Purpose and exact behavior changed: added a bounded strict JSON ingestion path
that rejects duplicate object member names at every depth before any
conversion or canonicalization. Every protocol `from_json` entry point (adapter
request/response, attestation, evidence result and payload, runtime facts,
report envelope) and the runtime-facts canonical check now parse through it.
Input larger than 8 MiB is rejected before parsing, malformed or over-deep input
stays bounded by the parser recursion limit, and the original bytes are never
modified so callers retain them for verification.
Spec/API/schema/DB/authority impact: stricter ingestion at existing boundaries.
No schema, DTO field, wire shape or CLI change; valid records parse identically.
A self-consistent transport hash or a permissive parse still never creates
verification authority.
