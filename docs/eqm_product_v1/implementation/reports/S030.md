## Scope

DEV-009 requires shared-source references, target dependencies and cycles to be
resolved deterministically in graph preparation before any affected analysis,
so transitive shared-source ownership is explicit and missing or cyclic
dependencies reject.

## Representation

- `crates/eqm_domain/src/graph.rs`: `WorkspaceGraphInput` gains
  `source_components: Vec<SourceComponent>`; `WorkspaceGraph` indexes them by
  `SourceComponentId`; `WorkspaceGraphBuildError::DuplicateSourceComponent` and
  `WorkspaceGraph::source_components()` are added. The index is preserved by
  `into_input`.
- `crates/eqm_engine/src/resolve.rs`:
  - `duplicate_findings` now reports duplicate source-component authority as the
    existing `EQM-E0300` finding, so `resolve_graph` returns stable diagnostics
    before index construction.
  - `dangling_findings` requires every target `source_components` reference and
    every target `depends_on` reference to resolve, and every source-component
    `dependencies` reference to resolve, as `EQM-E0301`.
  - `dependency_cycles` performs a deterministic topological peel (Kahn's
    algorithm over sorted authority keys) for source components and for targets;
    any node left in or downstream of a cycle reports `EQM-E0302`. This is the
    deterministic resolution boundary, not a filename or directory guess.

No new wire field, schema, digest domain, epoch or product identifier is
introduced. Transitive ownership materialization for artifact validation remains
the later S032/S033 concern.

## What this does not prove

engine boundaries. It does not author source components from workspace manifests,
materialize transitive ownership into artifact validation, or verify any source
content. No `cargo xtask verify`, Linux, coverage/mutation/fuzz/bench, release
packaging or signing lane was run. S030 is complete pending Codex acceptance;
S031 follows.
