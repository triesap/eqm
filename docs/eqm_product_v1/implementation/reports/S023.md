# Step report — S023 (model raw and semantic evidence identities)

Step ID/title: S023 — Model raw and semantic evidence identities

Baseline HEAD: `af5aab620ee5d66b32f3de689f421e5fa0ea0853` (S022 completion).
Resulting commit SHA: recorded in the external receipt / next ledger update.

## Scope

S023 adds validated raw-object/semantic-evidence relation types and a conversion
result. It is additive and pure: no storage, index, receipt or trust promotion,
and no change to existing v1 wire records or signed originals. Storage and
receipt idempotence/conflict behavior remain with S060 and S080–S084.

## Domain representation

`crates/eqm_domain/src/evidence_result.rs`:

- `RawEvidenceObject` preserves the exact received transport bytes (whitespace,
  member order included) and identifies them under the existing
  `RawObjectDigest` domain `eqm:v2:raw-object`. Construction rejects empty or
  over-bound input (`MAX_RAW_EVIDENCE_BYTES`, the established 16 MiB envelope) as
  `EvidenceResultBuildError::RawObjectBound`; it never normalizes bytes.
- `EvidenceIdentityRelation` binds one `RawEvidenceObject` to one
  `SemanticEvidenceDigest` (`eqm:v2:semantic-evidence`). It exposes
  `raw()`, `raw_digest()` and `semantic_identity()`. Holding the relation grants
  no authority and persists nothing.

## Protocol conversion

`crates/eqm_protocol/src/evidence.rs` adds
`EvidenceResultDto::identity_relation(&self, raw_bytes)`. The raw identity is
computed over the exact passed bytes. The semantic identity is
`SemanticEvidenceDigest::hash_content` over the canonical JCS projection of the
parsed record with the transport-only `id` and `result_digest` members removed
and the semantic `profile_values` set canonicalized by complete member bytes
(exact duplicates are rejected). Alternate whitespace or object member order
therefore yields a different raw-object identity but the same semantic identity.
The existing `EvidenceResult` id/result digest and all v1 schemas and bytes are
unchanged; no wire field was added or reinterpreted.

## Tests added and what each proves

`crates/eqm_protocol/src/evidence.rs`:

- `alternate_transport_bytes_share_semantic_identity`: compact and pretty
  encodings of the same record differ in raw identity, agree semantically, and
  each relation returns its exact original bytes unchanged.
- `changed_assertion_changes_semantic_identity`: a changed assertion field moves
  the semantic identity.
- `raw_object_bound_is_enforced`: the empty raw object is a typed bound error.

These are the RA15 contributions owned by S023. RA15 is a multi-step regression
(S023, S060, S080–S084); storage-level idempotence, duplicate delivery and
conflict persistence remain pending at their owning steps.

## Corrective checkpoint S023-R1 — bytes-first lossless v2 evidence identity (DEV-009 RF32/RF33)

**Scope:** DEV-009 S023-R1. **Baseline HEAD:**
`487539c67398f59f79c4a3f19ec81b13ec0c2ec5` (S022-R1; reviewed source `d6261c4`).
**Resulting commit SHA:** recorded in the next ledger update (no self-reference).
**Commit subject:** `fix: bind raw evidence to lossless v2 assertions`.

RF32: the newly added `EvidenceResultDto::identity_relation(&self, raw_bytes)`
accepted unrelated non-JSON bytes and bound them to `self`'s semantic identity.
RF33: it hashed a v1 default serialization under the v2 semantic domain, so the
legal neighboring attachment sizes `9007199254740992` and `9007199254740993`
collapsed to one `SemanticEvidenceDigest` after JCS numeric rounding, and v1
null/time/set forms did not establish ADR-0013 semantics.

### Representation

The v1 relation helper and its private `canonicalize_evidence_set` helper were
removed. All established v1 APIs (`from_json`, `From<&EvidenceResult>`, DTO
shapes, schemas and signed bytes) are unchanged. No v1 serializer now runs under
a v2 domain.

`crates/eqm_protocol/src/v2.rs` adds `CheckedEvidenceResultV2`, a bytes-first
checked result with private fields:

- `CheckedEvidenceResultV2::from_bytes(bytes)` parses the exact input once
  through the existing strict v2 reader (`EvidenceResultV2Dto::from_json`, which
  rejects duplicate members, wrong exact schema, invalid digests, noncanonical
  v2 tokens, explicit `null` optionals and inconsistent counts), then retains the
  original bytes and the canonical semantic bytes.
- `EvidenceResultV2Dto::checked_identity(&self, raw_bytes)` is the
  receiver-plus-bytes convenience entry: it reparses and revalidates `raw_bytes`
  and requires record equality, returning `V2DtoError::RecordMismatch` otherwise.
- The semantic root is every `EvidenceResultV2Dto` assertion member except
  `schema`, `id` and `result_digest`: subject, target, unit, requirements,
  facets, kind, evidence_spec_digest, contract/binding/policy digests, present
  runner/adapter/runtime/release references, profile_values, producer,
  claimed_trust, observed_at, payload and attachments. It is produced by the v2
  DTO's own representations (WireUint, CanonicalInstant, absence by omission,
  `CanonicalSet` members and ordered attempts) and canonicalized as JCS. There is
  no semantic extension member in this DTO, so none was added or pretended.
- Accessors are read-only: `record()`, `raw_bytes()`, `raw_identity()`,
  `semantic_bytes()`, `semantic_identity()`. Hash domains are the existing
  `eqm:v2:raw-object` (`RawObjectDigest`) and `eqm:v2:semantic-evidence`
  (`SemanticEvidenceDigest`). There is no public constructor, so an arbitrary
  DTO cannot be promoted without revalidation.

The generic domain pair (`RawEvidenceObject` / `EvidenceIdentityRelation`)
remains available as non-authorizing data; the checked admission capability now
lives only in the protocol type.

### Bounds

Two separate published bounds are honored and tested independently: the evidence
JSON ingress (`crate::strict::MAX_JSON_BYTES`, 8 MiB) applies to the checked v2
parse, while the generic raw-object carrier keeps its own 16 MiB envelope. No v1
range changed.

### Tests added and what each proves

`crates/eqm_protocol/src/v2.rs`:

- `checked_v2_literal_semantic_bytes_and_digest_match_independent_oracle`:
  reviewed 1,291-byte literal semantic projection and the independently
  recomputed `sha256:ac16d29887befa9ca8f5dbe8ab3379c3478858d248b573582f752e33e91c7f5f`
  (`SHA256("eqm:v2:semantic-evidence" || 0x00 || bytes)`).
- `checked_v2_separates_raw_and_semantic_identity`: compact and pretty encodings
  differ in raw identity, agree on semantic bytes and digest, and return the
  exact originals unchanged.
- `checked_v2_rejects_unrelated_bytes_and_mismatched_receiver`: a different v2
  family, non-JSON bytes, a foreign schema and a receiver/bytes mismatch reject.
- `checked_v2_large_values_stay_distinct_as_literal_decimals`: attachment sizes
  and count values `9007199254740992`/`9007199254740993` produce distinct
  semantic bytes containing the exact decimal strings.
- `checked_v2_every_semantic_axis_changes_identity_but_transport_members_do_not`:
  every assertion axis moves the semantic identity; changing `id` and
  `result_digest` together does not, while the raw identity moves.
- `checked_v2_set_permutations_agree_and_attempt_order_is_bound`: requirements and
  profile-value permutations agree; reversing ordered attempts differs.
- `checked_v2_rejects_duplicate_null_and_noncanonical_tokens`.
- `checked_v2_honors_evidence_ingress_bound_not_raw_carrier`: the 8 MiB ingress
  bound holds for the checked parse.

`crates/eqm_protocol/src/evidence.rs`:
`raw_object_carrier_bound_is_enforced_separately_from_evidence_ingress` proves the
generic 16 MiB carrier bound and its rejection above it; the v1 relation tests
were removed with the helper.
