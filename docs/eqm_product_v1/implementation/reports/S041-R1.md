Purpose and exact behavior changed:
Every cohort assignment now retains an authored target/provider configuration
claim alongside the S038 content axes, with exactly one claim required. The
authored claim is validated SHA-256 text, retained rather than substituted; the
graph projection includes it. `resolve_cohort` first requires the supplied
cohort to be the exact graph-owned `(id, revision, value)`; an absent or
altered caller-created record is rejected with `NotInGraph`. It then resolves
exactly one scenario revision, requires all and only occurrences with complete
content axes, and compares each authored configuration claim to the
independently projected typed graph configuration. Wrong kind is
`ConfigurationKind`; a differing valid claim is `ConfigurationMismatch`; the
typed graph projection is used as authority. `ResolvedCohort` retains the exact
cohort and scenario identity for consumption.

`prepare` now validates every loaded cohort before a prepared session can
succeed, using the application preparation boundary where the graph
projections exist, so no finalized session returns with a dangling, ambiguous
or incomplete cohort. The pure engine remains free of any manifest/protocol
dependency. Resolution and matching still grant no acquisition or trust, and
the authored N/N+1 cohorts remain separate combinations rather than a support
window.

Spec/API/schema/DB/authority impact:
Additive domain fields, authored/protocol members, application resolution
behavior and a `SessionError::Cohort` variant. Two v2 schemas were regenerated;
v1 schemas/bytes are untouched. No dependency was added. Optional manifest
member value constraints (null/SHA/marker) remain owned by the following P03-R4
correction.
