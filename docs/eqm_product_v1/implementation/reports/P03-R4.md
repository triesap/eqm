Purpose and exact behavior changed:
Comparison checked ingress now rebuilds the owning `eqm_domain::Profile` from
each selected definition and validates it with the shared domain construction
rules: `Title`, `OwnerRef` and `Description` text rules, nonempty owners,
nonempty finite dimensions, duplicate logical dimension/default keys, defaults
within declared values, and recursive extension namespace/depth/node/byte
bounds via `Extensions::new`. Deserialization alone still grants no trust; the
rebuilt profile is a validation artifact only.

The authored provider/cohort schemas now carry exact schema-marker `const`
values, `sha256:<64 lowercase hex>` patterns on every digest claim, nonempty
owner/assignment sets, and absent-or-present (never `null`) optionals. The v2
graph provider/cohort member schemas constrain owner sets and the comparison
profile-definition owners to non-null nonempty strings. No v1 schema, byte or
digest changed; no dependency was added. Raw token, NFC/duplicate and
cross-field checks remain reader layers, and JSON Schema validation is not
claimed as material trust.

Spec/API/schema/DB/authority impact:
Additive protocol/domain validation and four regenerated v2 schemas. No v1
schema changed. `schemas/v2/protocol/comparison-context.schema.json` gained a
nonempty owners constraint; `semantic-graph.schema.json` gained the graph
provider owners constraint.
