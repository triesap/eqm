Purpose and exact behavior changed: added the single host evaluation-time
capture boundary `eqm_application::clock::host_evaluation_time`, carried an
explicit `evaluation_time` on the application `SessionRequest` and
`PreparedSession`, and made the CLI capture it once per request (or accept an
explicit instant via `SessionRequest::at`). `matrix` now renders its invocation
context from the prepared session's injected time, and `release_check` captures
one instant, threads it into the session request and the release context, and no
longer reads `SystemTime` internally. Acquisition timing and monotonic process
timers are untouched.
Spec/API/schema/DB/authority impact: internal application/CLI time plumbing. No
schema, DTO, wire, storage or command grammar change. `Cargo.lock` updated
intentionally for the `chrono` application dependency; checks ran `--locked`.
