Purpose and exact behavior changed:
`ResolvedCohort` now retains the exact graph-owned `Cohort` value in addition to
its identity and independently derived expected axes. Before
`evaluate_checked_comparison` matches any candidate, it requires the carrier's
resolved scenario to equal the selected exact scenario, the retained cohort value
to equal the consuming immutable graph's exact ID/revision entry, and an
independent re-resolution of that retained value against the consuming graph to
reproduce the carrier's expected axes. This is value authority, not pointer
identity: independently prepared equivalent graphs still pass, while foreign,
wrong-scenario, altered same-ID/revision and re-configured target/provider
authority is rejected with a typed cause (`CohortScenario`, `CohortNotInGraph`,
`Cohort(CohortError)`) before eligibility. No new wire digest/domain, no raw
digest cast/hash, no trust promotion, and no graph identity binding were added.
The candidate `SubjectManifestDigest` remains retained separately. The graphless
`match_cohort_subjects` helper is documented as matching only its supplied
resolved authority and never claiming current-graph validation.

Spec/API/schema/DB/authority impact:
Additive typed error variants and an additive `ResolvedCohort::cohort()`
accessor. No schema byte, wire member, dependency or `Cargo.lock` change; v1
bytes untouched.
