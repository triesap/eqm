Purpose and exact behavior changed:
The comparison-context v2 wire family now has a bounded, bytes-first strict
reader. It validates the exact schema marker, typed SHA-256 references and the
selected-profile/dimension contract (exact declared dimensions, known values
inside their finite declaration, unknown without a value, no duplicate profile
or dimension logical key) and rejects explicit `null`, unknown members and
malformed states. A `CheckedComparisonContextV2` retains the exact raw bytes,
the canonical four-member semantic bytes (`contract_digest`, `scenario_digest`,
`profiles`, `comparison_rule_digest`, excluding only the schema marker) and a
typed `ComparisonContextDigest`; deserialization alone grants no trust. The
protocol reader reproduces the manifest projection's canonical bytes and digest
exactly.

The pure engine now carries a closed v2 comparison eligibility result with
`ComparisonParticipant` keeping `ComparisonContextDigest` and
`SubjectManifestDigest` as distinct types. Two independently matched, genuinely
different exact subjects sharing one comparison context are eligible; a
mismatched shared context is ineligible; missing context or subject coverage is
incomplete. Eligibility is explicitly not equivalence, conformance or trust, so
later evaluator/trust steps retain ownership. The shared application path
derives the comparison identity from the immutable prepared graph and an
explicit approved rule reference, rejecting any scenario, policy or profile not
already a member of that graph (no reload, latest lookup, clock capture,
policy-digest substitution or invented rule format). The v1 equivalence surface
is unchanged.

Spec/API/schema/DB/authority impact:
Additive public protocol, engine and application APIs. No schema byte, v1 byte,
wire member or dependency changed; the comparison schema is unchanged and
`cargo xtask schemas check` passes. No domain/engine effectful dependency was
added; the application module stays on the existing dependency direction.
