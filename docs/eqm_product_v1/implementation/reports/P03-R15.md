Purpose and exact behavior changed:
RF69 reproduced that `CapabilityV2Dto.title` (and every other length-only text
helper) admitted a literal U+0000 while the owning `Title::new` rejected it. The
owning `eqm_domain::entity::normalized_text` predicate rejects every Unicode
control code point except LF and TAB, and additionally requires nonempty NFC
text within a UTF-8 byte bound. The schema-expressible forbidden-control subset
is now applied to the exact helpers used by the owning carriers: `Title`,
`Description`, `SelectorText`, `RouteSelector`, `RequirementStatement`,
`TransitionTrigger` and `WaiverReason`, plus the authored v2 `SelectorText`
(cohort id and assignment `build_id`).

No input is normalized, and the rule was not applied to raw/observed bytes,
diagnostics, opaque payload text or extension values. NFC and UTF-8 byte length
remain explicit owning layers that JSON Schema cannot faithfully prove; the
generated `minLength`/`maxLength` and the control pattern are the faithful
code-point subset.

## Affected field → owning predicate audit

| Helper | Owning carrier | Owning predicate / bound | Schema expression |
|---|---|---|---|
| `title_schema` | `Title` | `normalized_text` / 160 bytes | min 1, max 160, control pattern |
| `description_schema` | `Description`, `RequirementStatement` | `normalized_text` / 4,096 bytes | min 1, max 4096, control pattern |
| `selector_text_schema` | `SelectorText`, `RouteSelector` | `normalized_text` / 512 bytes | min 1, max 512, control pattern |
| `transition_trigger_schema` | `TransitionTrigger` | `normalized_text` / 256 bytes | min 1, max 256, control pattern |
| `waiver_reason_schema` | `WaiverReason` | `normalized_text` / 2,048 bytes | min 1, max 2048, control pattern |
| authored `selector_text_schema` | `SelectorText` (v2 cohort) | `normalized_text` / 512 bytes | min 1, max 512, control pattern |

Forbidden set: `U+0000–U+0008`, `U+000B–U+001F`, `U+007F–U+009F`; LF (`U+000A`)
and TAB (`U+0009`) stay accepted. Identifier, owner, digest, path, environment,
secret, repository and calendar helpers already constrain their vocabularies
with ASCII-only patterns, so they were not changed.
