Purpose and exact behavior changed:
A `cohort` v2 authored manifest is discovered through the existing
`contract_sources` with the exact root `id`, `revision`, `scenario`,
`assignments` and `extensions`. Assignments reuse the S038 content axes
(repository, source commit, source/component content, build and artifact) and
are keyed by unique occurrence; target/provider configuration remains
graph-backed authority and is never copied from the authored document. The v2
semantic graph gains a `cohorts` collection.

`resolve_cohort` resolves the cohort scenario against the immutable graph and
rejects zero or multiple matching scenario revisions instead of choosing a
"latest". It requires all and only scenario occurrences to be assigned, requires
each assignment to carry a complete content axis set, and derives each expected
configuration from the graph projection. `match_cohort_subjects` then matches a
checked candidate subject manifest against that independently supplied authority
through the existing bytes-first S038 matching; undeclared combinations and
absent participants reject. Separate cohorts are separate approved
combinations, never an inferred support window, and resolution/acquisition grants
no trust.

Spec/API/schema/DB/authority impact:
Additive domain cohort authority, graph collection, authored manifest schema and
application resolution API. v1 schemas/bytes are unchanged; no dependency was
added. The v2 graph goldens gained the empty `cohorts` member (recorded below).
