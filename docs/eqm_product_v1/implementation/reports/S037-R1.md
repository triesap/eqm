Purpose and exact behavior changed:
The domain `Scenario` now has a complete authored path. `contract_sources`
dispatches the exact v2 `scenario` manifest kind (no new flags or aliases); the
strict DTO carries `id`, `revision`, `participants` (unique occurrence `id`,
explicit `role`, tagged `target`/`provider` subject) and directed `dependencies`
(`from`/`to`), with `extensions`. Conversion validates typed IDs and exactly one
subject tag, then the domain rejects duplicate occurrences, unknown/self/duplicate
dependency endpoints, preserving repeated target/provider occurrences as distinct
canonical members. Graph construction indexes scenarios by exact `(id, revision)`
and rejects duplicate authority. Resolution requires scenario target subjects to
name a declared target; provider subjects remain explicit unresolved and
non-authorizing until the provider step. The complete v2 graph identity gains the
`scenarios` collection and rejects v2-only scenario authority in its v1
projection; the v2 semantic-graph schema was regenerated with the new collection.

Spec/API/schema/DB/authority impact:
Additive `SchemaKind::Scenario`, a new generated `schemas/v2/manifest/scenario.schema.json`,
and the updated v2 semantic-graph schema. No v1 schema/bytes/digest change; no
dependency change; no new CLI surface.
