## Scope

DEV-009 allocates a `participation` v2 manifest kind discovered through the
existing contract sources, decoded by its own strict reader, converted into the
domain rule and resolved against the graph. No new CLI flag or workspace source
list alias is introduced.

## Representation

- `crates/eqm_domain/src/schema.rs` adds `SchemaKind::Participation`
  (`participation`) to the manifest group and the sorted `ALL` inventory.
- `crates/eqm_manifest/src/dto/v2.rs` adds the strict `ParticipationV2Dto`
  (`id`, `requirement`, `targets`, required typed `applicability`, extensions).
- `crates/eqm_manifest/src/validation.rs` decodes v2 participation under the
  contract source class and keeps every other non-v1 URI closed. The `DocumentDto`
  enum gains the `Participation` variant with its authority key.
- `crates/eqm_manifest/src/conversion.rs` adds `convert_participation`, which
  builds the domain rule through the existing typed applicability and extension
  helpers.
- `crates/eqm_manifest/src/loader.rs` pushes converted rules into graph input and
  records their source identity.
- `crates/eqm_domain/src/graph.rs` indexes participation by authority and exposes
  `participation()`; `crates/eqm_engine/src/resolve.rs` reports duplicate rule
  authority (`EQM-E0300`) and dangling requirement/target references
  (`EQM-E0301`).
- `schemas/v2/manifest/participation.schema.json` is generated by the versioned
  manifest generator; no schema is hand-written.

Profile existence and coordinate evaluation remain the immutable selected
context's concern (S036).
