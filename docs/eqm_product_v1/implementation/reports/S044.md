Purpose and exact behavior changed:
Selection orchestration is now owned by one application operation,
`eqm_application::prepare_obligations`. It takes one immutable finalized graph,
an explicit `EvaluationMode`, explicit versus development-default
`PolicyProfileRequest`s from an explicit authority origin, and an optional
release context, then runs the existing engine selection, builds the validated
applicability context, and derives the complete obligation universe. The CLI
`evaluation` module is reduced to a thin adapter that parses profile arguments
and resolves the one development policy revision. `reconcile` now calls the
application applicability builder. No selection rule, wire member, schema byte,
dependency or `Cargo.lock` entry changed; `eqm_domain`/`eqm_engine` stay pure.
