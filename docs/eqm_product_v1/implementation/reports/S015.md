## Corrective checkpoint S015-R1 — restore v1 acceptance and fix v2 integer forms

**Scope:** DEV-002 corrective checkpoint S015-R1 (RF01/RF03/RF04/RF05).
**Baseline HEAD:** `cb57c6c85faaa58d827f3355aae0aa54b41b1232`.
**Commit SHA:** recorded externally; backfilled into the ledger in S015-R2.

Files/modules changed: `crates/eqm_protocol/src/wire.rs`,
`crates/eqm_protocol/src/evidence.rs`, `crates/eqm_protocol/src/records.rs`,
`crates/eqm_runner/src/inventory.rs`, `crates/eqm_protocol/tests/wire_form_schema.rs`
(new), `Cargo.toml`, `crates/eqm_protocol/Cargo.toml`, `Cargo.lock`.

Behavior changed:

- **RF01 restored.** The S015 v1 numeric-range restriction was removed from all
  three sites: `validate_counts` no longer applies `exact_unsigned`; runtime-fact
  and inventory `FactValueDto::Integer` validation no longer applies
  `exact_signed`. v1 counts and integer facts again accept the full `u64`/`i64`
  domains with identical schemas and bytes. `cargo xtask schemas check` confirms
  the 22 v1 schema documents are byte-identical.
- **RF03 fixed.** `parse_signed_decimal` parses the magnitude as an unsigned
  value before negation, so `"-9223372036854775808"` (`i64::MIN`) round-trips
  instead of overflowing; one-past endpoints reject.
- **RF04 fixed.** Both decimal-string visitors reject strings whose value lies
  inside `|n| <= 2^53-1`; only out-of-range values may use the string form.
  Negative zero, leading zeros, plus signs, fractional and exponent strings, and
  negative-string unsigned forms reject.
- **RF05 fixed.** The generated `WireUint`/`WireInt` primitive schemas now encode
  the exact representable string ranges (not a bare digit regex) and reject
  `"-0"`. `decimal_range_alternation` builds a flat, exact ECMA alternation for
  each numeric range.

Required tests added and what each proves: `wire::tests` cover the full
`u64`/`i64` endpoints, safe-boundary neighbours, small-value strings, negative
zero, fractional/exponent tokens and one-past overflow for both parsers;
`generated_range_patterns_match_small_ranges_exactly` brute-forces the range
encoding over small ranges against an independent matcher;
`tests/wire_form_schema.rs` decides each generated primitive schema (integer
branch numerically, string branch with the generated pattern) over the same
boundary corpus that drives the parser and fails on any disagreement;
`counts_accept_the_full_v1_integer_range`,
`runtime_facts_digest_subject_and_order_are_strict` (with an `i64::MAX` fact) and
`inventory_integer_attributes_keep_the_full_v1_range` prove the v1 restoration at
the public DTO/validation boundaries, not only via helpers.

Schema/API/authority impact: no v1 schema, URI, DTO field or signed byte changed;
the `eqm:v2` string form remains unexposed to generated schemas until S015-R2/R3.
The only dependency change is a test-only, zero-dependency `regex-lite = "=0.1.9"`
dev-dependency of `eqm_protocol`, required to execute the generated schema
patterns against the parser; `Cargo.lock` records it exactly and checks ran
`--locked`.
