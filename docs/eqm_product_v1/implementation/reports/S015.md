Purpose and exact behavior changed: implemented the ADR-0013 exact-numeric rule.
Added the canonical v2 wire types `WireUint`/`WireInt` (integer in the exact
`|n| <= 2^53-1` range, unsigned/signed decimal string beyond, canonical
serialization, duplicate/leading-zero/plus/fractional/overflow rejection) and
`exact_unsigned`/`exact_signed` helpers. The current-only v1 contract remains
integer-only: `CountsDto` validation and runtime-fact/inventory integer facts now
reject values beyond the exact range instead of accepting an ambiguous number.
The concrete ADR-0013 numeric vectors are executed as controls against the wire
types. Canonical timestamp enforcement was already active (AutoSi, corrected in
CR03); this step adds the numeric half.
Spec/API/schema/DB/authority impact: no v1 schema byte changed; `cargo xtask
schemas check` passes unchanged because no DTO wire shape changed. `Cargo.lock`
updated intentionally for the `serde_json` test-only dependency of
`eqm_test_support`; all checks ran `--locked`.

## Self-review

Diff inspected for unrelated changes: only wire-form enforcement, the v2 wire
types, tests and a test-only dependency changed. No v1 schema or signed byte was
rewritten; existing v1 integer forms still parse.
Findings corrected in this same step: initially attempted to widen the v1 DTO
numeric shape to an integer/string union; that would change the v1 schema
contract against ADR-0013/CR03, so it was reverted in favour of v1 exact-range
rejection plus v2 wire types.
Remaining risks / owner decisions / deviations: the approved `eqm:v2` namespace
has no allocated step that creates version-parallel DTOs, a v2 generator, and v2
URI parity. The decimal-string alternative is therefore available as canonical
types and frozen vectors but is not yet exposed in generated v2 schemas. This is
flagged for Codex; it does not block the current-only v1 contract or the
numeric-exactness guarantee (out-of-range v1 values are rejected, not silently
changed). Null/absence and set/sequence enforcement (S016 and its owning steps)
are not claimed here.
