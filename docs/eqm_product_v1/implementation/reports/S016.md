## S016 — canonical collection and authored-text enforcement

Scope: enforce the DEV-004 v2 field classification at the real v2 consumers.
Baseline HEAD: `ed06989e45a82c24d94d03f0a85f02905860c069` (S016-P1).

Files/modules changed:
- `crates/eqm_protocol/src/canonical.rs` (new): reusable `CanonicalSet<T>`
  boundary plus `canonical_member_bytes` and `is_authored_nfc`.
- `crates/eqm_protocol/src/lib.rs`: module registration and re-exports.
- `crates/eqm_protocol/src/v2.rs`: the five v2 families use `CanonicalSet` for
  their unordered collections, keep `Vec` for ordered sequences, add NFC and
  logical-key validation, and bind the runtime-facts digest to the canonical
  semantic set projection.
- `crates/eqm_domain/src/entity.rs`, `lib.rs`: public `is_nfc_text` predicate.
- `crates/eqm_test_support/src/vectors.rs`, `tests/wire_vectors.rs`: new
  `Set`/`Sequence`/`AuthoredText`/`OpaqueBytes` disciplines, corrected
  `RV-TEXT-2`, and opaque decomposed/non-UTF-8 controls.
- `crates/eqm_protocol/tests/canonical_collections.rs` (new) and the
  `canonical.rs` unit tests: real-ingress permutation/duplicate/ordering traps.
- `schemas/v2/protocol/*.schema.json`: regenerated atomically.

Exact behavior changed:
- Unordered semantic sets now sort by each member's complete canonical JSON
  UTF-8 bytes, not Rust `Ord`, a key tuple or received order. Valid permutations
  produce an equal value and identical canonical bytes; exact duplicate members
  are rejected before collection. `CanonicalSet` is used for target sets,
  requirements, facets, attachments, profile values, runtime facts and inventory
  entries.
- Ordered sequences (`attempts`, `diagnostics`, `related` locations) stay `Vec`
  and keep order and multiplicity; attempt-index validity is unchanged.
- Object maps (`attributes`) keep strict duplicate-member ingestion and JCS
  key ordering.
- New logical-key checks: `(profile, dimension)` and conflicting revisions per
  profile; `(surface, dimension, key)` facts; `(kind, key)` inventory entries;
  attachment name. These are independent of canonical ordering.
- Authored metadata is rejected when not NFC without normalization: targets,
  requirements, facets, units, selector metadata, profile/symbolic values,
  attachment names. The original claim of manual-review reviewer validation was
  incorrect: the payload validator ignores reviewer (RF20). Observed payload text,
  diagnostics, source exports and opaque attachment bytes are not NFC-checked.
- `RuntimeFactsV2Dto` binds `facts_digest` to the canonical semantic set
  projection (unordered `facts`/`profile_values` canonically ordered before JCS)
  while preserving original bytes and all S015 numeric/time/bound checks. No
  digest domain or trust semantics changed.

Canonicalization/digest and schema impact: canonical order is now protocol
behavior, not serializer convention. The five v2 schemas were regenerated; the
set properties reference `CanonicalSet_*` definitions with `uniqueItems: true`.
The 22 v1 schemas are byte-identical (`git diff --name-only -- schemas/v1` is
empty). No dependency or `Cargo.lock` change; every command ran `--locked`.

## Corrective checkpoint S016-R1 — validate authored v2 metadata at ingress

**Scope:** DEV-005 (RF20/RF21). Baseline HEAD:
`c14ac20dffac451380b1b2bea771a575b0ba8bd9` (the DEV-005 planning commit).
**Commit SHA:** recorded externally; backfilled into the ledger in S016-R2.

Replace the NFC-only authored predicate with the DEV-005 field/type mapping at
every existing v2 `from_json` root and on the embedded adapter-response
inventory. Validation reuses the existing domain constructors and closed
vocabularies, so an exact-NFC string that violates a typed identifier's grammar,
length or vocabulary now fails. Validation rejects; it never normalizes. No
blanket NFC rule is applied to observed payload text, diagnostic prose, source
exports or opaque attachment bytes.

| v2 field family | Contract now enforced |
| --- | --- |
| Evidence target/unit/requirements/facets | `TargetId`, `UnitId`, `FullRequirementId`, `Facet` |
| Shared subject scope | `TargetId` target and target-set members, `ProviderId` provider, nonempty target set |
| Shared subject metadata | `RepositoryIdentity`, digests, `SourceCommit`, optional `SelectorText` build ID, optional artifact digest, shared across evidence/runtime-facts/inventory/request roots |
| Profile values | `ProfileId`, positive `Revision`, `DimensionId`, `SymbolicValueId`; unique `(profile, dimension)` and consistent per-profile revision retained |
| Manual review | `OwnerRef` reviewer plus the passed/failed outcome vocabulary |
| Attachments | `SelectorText` name and media type, digest syntax, name uniqueness |
| Inventory / adapter request / response | `AdapterId`, `TargetId`, shared subject, `InventoryCompleteness`, entry metadata; embedded inventory runs the same structural checks |
| Inventory entries / runtime facts | `SelectorText` kind/key/attribute names, `SymbolicValueId` symbol values, `SelectorText` text values, `RepoPath` source, `SurfaceId`/`DimensionId`/`SelectorText` fact keys |
| Diagnostics | optional `UnitId`/`TargetId` references only; prose and source exports keep their existing contracts |
| Selector helper | `SelectorText`/`HttpMethod`/`ReleaseChannel` typed contract |

Files/modules changed:
- `crates/eqm_protocol/src/v2.rs`: typed shared subject/scope, profile, fact,
  inventory-entry, diagnostic and payload validation; the five roots and the
  embedded inventory call it. New `V2DtoError::InvalidProfile`/`InvalidEntry`.
- `crates/eqm_protocol/tests/canonical_collections.rs`: replaced the invalid
  `unit = "café"` positive control and the `R18`/`facet.a` fixtures with valid
  typed `UnitId`/`FullRequirementId`/`Facet` controls; the composed/decomposed
  Unicode proof now uses a Unicode-capable `SelectorText` field.
- `crates/eqm_protocol/tests/v2_authored_ingress.rs` (new): valid controls plus
  one-field mutants for every mapped family at its owning `from_json` root and
  through the embedded inventory.

Behavior changed: authored v2 metadata that is NFC but violates a typed grammar
(single-segment `UnitId`, unqualified requirement, unknown facet/vocabulary,
uppercase symbol/identifier, empty or over-long selector text, invalid
`RepoPath`, non-positive profile revision, invalid reviewer) now rejects at the
owning ingress. The subject checks previously applied only to runtime facts are
shared with the evidence, inventory and adapter roots. Runtime-facts mutants
recompute the enclosing digest, so each negative is the authored check rather
than a digest mismatch.

Schema/hash/identity impact: no DTO shape changed, so no schema bytes changed;
`schemas/v2` and the 22 `schemas/v1` documents are unchanged and `Cargo.lock` is
unchanged. No digest domain, trust or relationship semantics changed. All S015
controls and the S016 canonical-set/sequence/text tests are retained.

Tests added and what each proves:
- `v2_authored_ingress::evidence_result_rejects_one_field_metadata_mutants`:
  target/unit/requirements/facets/kind/trust/producer/subject/attachment/profile
  single-field mutants reject through `EvidenceResultV2Dto::from_json`, and the
  manual-review reviewer/outcome are validated.
- `v2_authored_ingress::runtime_facts_rejects_one_field_metadata_mutants`:
  provider/target/subject/fact-coordinate/value/profile mutants reject after the
  digest is recomputed.
- `v2_authored_ingress::inventory_rejects_one_field_metadata_mutants`:
  adapter/target/completeness/subject/entry kind/key/attribute/source and
  diagnostic unit/target mutants reject through `InventoryV2Dto::from_json`.
- `v2_authored_ingress::embedded_inventory_rejects_the_same_metadata_mutants`:
  the same checks run through the adapter-response root.
- `v2_authored_ingress::adapter_request_and_response_reject_metadata_mutants`:
  adapter/target/subject mutants reject through the request/response roots.
- `canonical_collections::authored_metadata_rejects_non_nfc_without_normalizing`:
  the Unicode positive control moved to valid `SelectorText` metadata; typed IDs
  reject on grammar; closed selector vocabularies reject off-vocabulary spellings.
