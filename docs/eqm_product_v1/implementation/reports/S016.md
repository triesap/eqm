## S016 — canonical collection and authored-text enforcement

Scope: enforce the DEV-004 v2 field classification at the real v2 consumers.
Baseline HEAD: `ed06989e45a82c24d94d03f0a85f02905860c069` (S016-P1).

Files/modules changed:
- `crates/eqm_protocol/src/canonical.rs` (new): reusable `CanonicalSet<T>`
  boundary plus `canonical_member_bytes` and `is_authored_nfc`.
- `crates/eqm_protocol/src/lib.rs`: module registration and re-exports.
- `crates/eqm_protocol/src/v2.rs`: the five v2 families use `CanonicalSet` for
  their unordered collections, keep `Vec` for ordered sequences, add NFC and
  logical-key validation, and bind the runtime-facts digest to the canonical
  semantic set projection.
- `crates/eqm_domain/src/entity.rs`, `lib.rs`: public `is_nfc_text` predicate.
- `crates/eqm_test_support/src/vectors.rs`, `tests/wire_vectors.rs`: new
  `Set`/`Sequence`/`AuthoredText`/`OpaqueBytes` disciplines, corrected
  `RV-TEXT-2`, and opaque decomposed/non-UTF-8 controls.
- `crates/eqm_protocol/tests/canonical_collections.rs` (new) and the
  `canonical.rs` unit tests: real-ingress permutation/duplicate/ordering traps.
- `schemas/v2/protocol/*.schema.json`: regenerated atomically.

Exact behavior changed:
- Unordered semantic sets now sort by each member's complete canonical JSON
  UTF-8 bytes, not Rust `Ord`, a key tuple or received order. Valid permutations
  produce an equal value and identical canonical bytes; exact duplicate members
  are rejected before collection. `CanonicalSet` is used for target sets,
  requirements, facets, attachments, profile values, runtime facts and inventory
  entries.
- Ordered sequences (`attempts`, `diagnostics`, `related` locations) stay `Vec`
  and keep order and multiplicity; attempt-index validity is unchanged.
- Object maps (`attributes`) keep strict duplicate-member ingestion and JCS
  key ordering.
- New logical-key checks: `(profile, dimension)` and conflicting revisions per
  profile; `(surface, dimension, key)` facts; `(kind, key)` inventory entries;
  attachment name. These are independent of canonical ordering.
- Authored metadata is rejected when not NFC without normalization: targets,
  requirements, facets, units, selector metadata, profile/symbolic values,
  attachment names. The original claim of manual-review reviewer validation was
  incorrect: the payload validator ignores reviewer (RF20). Observed payload text,
  diagnostics, source exports and opaque attachment bytes are not NFC-checked.
- `RuntimeFactsV2Dto` binds `facts_digest` to the canonical semantic set
  projection (unordered `facts`/`profile_values` canonically ordered before JCS)
  while preserving original bytes and all S015 numeric/time/bound checks. No
  digest domain or trust semantics changed.

Canonicalization/digest and schema impact: canonical order is now protocol
behavior, not serializer convention. The five v2 schemas were regenerated; the
set properties reference `CanonicalSet_*` definitions with `uniqueItems: true`.
The 22 v1 schemas are byte-identical (`git diff --name-only -- schemas/v1` is
empty). No dependency or `Cargo.lock` change; every command ran `--locked`.
