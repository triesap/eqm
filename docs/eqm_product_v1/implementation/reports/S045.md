Purpose and exact behavior changed:
Request parsing for repeatable `--profile` arguments previously collected into a
`BTreeMap<ProfileId, _>`, silently overwriting a second selection of the same
profile ID (last-write-wins). The adapter now parses each argument and rejects a
repeated profile ID with an explicit diagnostic before selection, so caller
intent can never be silently discarded. Engine request construction already
rejected duplicate exact profile authority (`DuplicateProfile`) and duplicate
dimensions (`DuplicateDimension`); those owners now have direct tests. No
selection rule, wire member, schema byte, dependency or `Cargo.lock` changed.
