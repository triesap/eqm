Purpose and exact behavior changed: introduced documented narrow ports.
`AuthorityProvider` reads protected already-finalized graph authority for an
explicit `AuthorityRequest`. `EvidenceReader` performs a bounded read of stored
`EvidenceResult` records for an explicit `EvidenceReadRequest` (limit 1..=10,000).
`Executor` runs one already-approved acquisition plan and returns a terminal
`AcquisitionReceipt`. `EvidenceVerifier` returns a structured, explicitly
non-authorizing `VerificationReport`. The `Capabilities` container exposes each
port only on demand and returns an explicit `CapabilityError` when a required
capability is absent. There is no default implementation, global runtime, or
permissive fallback, and read/evaluation paths request only the reader, so they
structurally cannot reach execution or verification.
Spec/API/schema/DB/authority impact: new internal application port surface. No
schema, DTO, wire, storage or CLI grammar change. No trust is minted; the
verification report is documented as non-authorizing until the protected
verification step.
