Purpose and exact behavior changed:
An explicit provider authority record now exists with exactly `id`,
`configuration_digest`, `owners` and `extensions`. The declared
`configuration_digest` is an external content reference; it is deliberately
distinct from the `eqm:v2:provider-configuration` identity the canonical
projection derives over the whole validated definition. Targets gain an exact
`providers` reference set (no universal or implicit attachment), and the v2
semantic graph gains a `providers` collection. Authored provider documents use
the new `provider` v2 manifest kind discovered through the existing
`contract_sources`, with no new CLI flags or source-list aliases.

Preparation now fails closed when a target, requirement or scenario participant
references a provider absent from the declared authority; an unreferenced
declared provider is simply not attached to any target. The protocol
expected/assignment carriers use the typed `ProviderConfigurationDigest` for
the provider configuration axis without renaming the frozen
`provider_configuration_digest` entry. The temporary unresolved-provider
preparation positive was replaced with a known-provider positive and a
missing-provider negative. Declaring or loading a provider verifies no external
material and confers no trust.

Spec/API/schema/DB/authority impact:
Additive domain/provider manifest/graph/protocol schema and digest identity plus
new resolution findings. v1 schemas/bytes are unchanged. No new dependency was
added. The graph/comparison v2 goldens changed only by the additive `providers`
member (recorded below).
