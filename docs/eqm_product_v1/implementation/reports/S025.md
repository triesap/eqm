# Step report — S025 (validate evidence identity relationships)

Step ID/title: S025 — Validate evidence identity relationships
Requirement and acceptance IDs: R19, R21 / AC019, AC021.
Baseline HEAD: `5a2adfd5a68797df6a1a200277a443ccb99380f5` (S024-R1).
Resulting commit SHA: recorded in the next ledger update (no self-reference).

## Scope

DEV-009 freezes one protocol-to-domain checked admission over an already-parsed
v2 object plus explicit typed lineage, a declared execution and an independently
supplied expected context. No trust, storage or signature is created, and no v1
record is routed through an implicit conversion.

## Representation

`crates/eqm_protocol/src/admission.rs` (new) exports:

- `EvidenceAdmissionContext` — the immutable approved expectation: replay-bound
  subject (repository / repository-id digest / scope / source commit / build /
  artifact / target-configuration digest), target, unit, requirement, facet set,
  envelope kind, the four component digests, the four optional
  runner/adapter/runtime/release references, exact selected profiles, the
  explicit provider-to-target association and the expected plan/campaign
  authority. Every field is explicit; nothing is defaulted or zero-filled.
- `AdmittedEvidenceV2` — the private-field checked result, holding the domain
  `EvidenceResult`, the validated `EvidenceLineage`, the declared
  `EvidenceExecution`, the recomputed `SemanticEvidenceDigest` and the exact raw
  bytes. Only `admit_evidence` constructs it.
- `admit_evidence(checked, lineage, execution, context)` — the checked conversion.

Checks performed before construction:

1. `lineage.validate_against(execution, expected authority)` (S024-R1).
2. `id == result_digest == recomputed semantic identity` (the semantic projection
   excludes `schema`/`id`/`result_digest`), plus the exact v2 schema marker.
3. envelope kind against the expected kind.
4. subject axes (repository, repository-id digest, source commit, build,
   artifact, target-configuration digest) and scope equality.
5. target equality and scope membership; a provider scope requires the declared
   provider-to-target association (never ID equality or universal linkage).
6. unit equality and requirement ownership: every requirement's owning unit must
   equal the record unit, and the expected requirement must be covered.
7. facet set equality and the four component digests.
8. present/absent runner, adapter, runtime-facts and release-record references.
9. exact selected profiles (revisions and dimension values).
10. payload-kind consistency (enforced by the domain `EvidenceResult::new`), and
    runtime/release payload references matching the envelope.
11. count/outcome consistency (RA02): a positive count requires a matching
    attempt outcome and, conversely, an attempt outcome requires a positive
    matching count. Selected logical observations are not equated with retry
    count, and mixed retry history stays representable and non-success.

The older `EvidenceResultV2Dto::from_json` / `CheckedEvidenceResultV2::from_bytes`
structural readers remain distinct, non-admitting APIs.

## Tests added and what each proves

`crates/eqm_protocol/src/admission.rs`:

- `positive_fixture_admits_with_identity_and_relationships`: a sealed v2 fixture
  with `id == result_digest == recomputed semantic identity` admits and preserves
  the semantic identity, raw bytes and lineage.
- `identity_must_equal_the_recomputed_semantic_digest`: an equal `id`/
  `result_digest` that differs from the recomputed semantic identity rejects.
- `one_axis_mismatches_reject_before_admission`: kind, subject, target, unit,
  requirement, requirement-unit, facet, digest and profile each reject with their
  own typed error, mutating one axis at a time after a fresh parse.
- `provider_scope_requires_a_declared_association`: a provider scope without a
  declared association rejects, and admits only once the association is declared.
- `counts_must_not_contradict_attempt_outcomes` (RA02).
- `runtime_and_release_payload_references_must_match_the_envelope`: payload
  runtime/release references that diverge from the envelope reject.
- `lineage_mismatch_rejects_at_the_admission_boundary`.

## Corrective checkpoint S025-R1 — typed context and retry chronology (DEV-010 RF38/RF39)

**Scope:** DEV-010 S025-R1 / RF38 and RF39. **Baseline HEAD:**
`9ecbe00d214afe79065d75ac1571cede5227da3c` (S022-R2; reviewed source `49541e3`).
**Resulting commit SHA:** `75eb084cf91f3b6979f0f0c4b02caae74969e8de`.
**Commit subject:** `fix: retain typed evidence context and validate retry chronology`.

RF38: `EvidenceAdmissionContext` stored contract, binding, evidence-specification,
policy, runner and adapter identities as interchangeable `Sha256Digest`, losing
their approved typed domains at the new v2 boundary. RF39: numbered retry
chronology was not checked across attempts, so a resealed record with retry 2
before retry 1 inside the same aggregate window admitted.

### RF38 representation

`crates/eqm_protocol/src/admission.rs`:

- `EvidenceAdmissionContext` now uses the existing typed identities
  `EvidenceSpecificationDigest`, `ContractDigest`, `BindingDigest`,
  `PolicySelectionDigest`, `Option<RunnerDigest>` and `Option<AdapterDigest>`,
  plus an explicit `TargetConfigurationDigest`. Runtime-facts and release-record
  references have no distinct wrapper, so they remain exact structural
  `Sha256Digest` references and are not mislabelled as typed domains.
- Admission parses each transport string as a structural `Sha256Digest` and
  compares it with the typed expectation's `as_digest()`. The expected
  target-configuration SHA must equal the subject configuration field.
- `AdmittedEvidenceV2` retains and exposes the typed expectations through
  `evidence_spec_digest()`, `contract_digest()`, `binding_digest()`,
  `policy_digest()`, `target_configuration_digest()`, `runner_digest()` and
  `adapter_digest()`. The legacy generic `EvidenceResult` fields remain inside
  the checked wrapper for v1 compatibility.
- No public unchecked generic-SHA cast, cross-type conversion, digest rehash,
  invented digest domain or v1 representation change was added. Context
  identities are produced by the existing typed `hash_content` APIs.

### RF39 representation

- New `retries_are_ordered` requires each numbered retry to begin at or after
  the preceding retry's finish. Equal boundaries are allowed and the `Ord`
  comparison retains nanoseconds. It applies to every execution-bearing payload
  (`structural_check`, `test`, `snapshot`) at the admission boundary; the
  individual attempt window and aggregate containment checks are unchanged.
- New typed `EvidenceAdmissionError::RetryChronology` reports the violation. No
  `observed_at`/freshness rule is invented; those remain with later owning steps.

### Tests added

`crates/eqm_protocol/src/admission.rs`:

- `retained_typed_expectations_are_exposed`: the checked result exposes exactly
  the typed expectations that admitted it.
- `subject_core_reference_and_scope_mutants_reject`: one-axis mutants for every
  subject axis (repository, repository-id, source commit, build, artifact,
  target configuration), scope shape, each core digest (contract, binding,
  policy; evidence spec covered earlier), and present/absent runner/adapter,
  plus positive present-identity counterparts.
- `profile_revision_and_value_are_exact`: exact profile match admits; a changed
  value or revision rejects.
- `payload_kind_must_agree_with_envelope_kind`: a payload whose kind disagrees
  with the envelope rejects.
- `retry_chronology_control_accepts_ordered_and_rejects_reversed`: strictly
  sequential and equal-boundary subsecond positives, and reversed, overlapping
  and out-of-aggregate-window negatives, all through bytes-first sealed admission.
- Executed doctests on `EvidenceAdmissionContext`: two `compile_fail` cross-domain
  controls (runner for adapter, contract for binding) plus a positive typed
  identity counterpart.
