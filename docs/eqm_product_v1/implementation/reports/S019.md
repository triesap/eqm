## S019-A — validated policy selection provenance inputs

**Scope:** DEV-006 S019 policy/profile carrier decision.
**Commit SHA:** recorded externally; backfilled by the next update.

Adds `crates/eqm_domain/src/selection.rs` with two fallible, private-field
carriers and exports them from `eqm_domain`:

- `SelectedDimensionStateV2` is explicit `Known(SymbolicValueId)` or `Unknown`.
- `SelectedProfileInputV2<'a>` retains the exact selected `Profile` definition
  plus every declared dimension with its explicit state. Construction rejects
  an undeclared dimension, a repeated dimension, a `Known` value outside the
  dimension's finite declaration, and a profile whose declared dimensions are
  not all present. A missing dimension is an error, not `Unknown`, and no
  development default is applied.
- `PolicySelectionInputV2<'a>` retains the exact selected `Policy` definition and
  the selected profile carriers. Construction rejects a duplicate profile ID
  (including the same ID at different revisions) and any selected profile-ID set
  that is not exactly the policy's required profile-ID set.

These carriers prove structural selection validity only. They confer no
protected authority, trusted execution, freshness or waiver standing, and the
engine selection algorithm is unchanged. `Vec` inputs are used where duplicates
must be rejected before map collection.

### Tests added

`crates/eqm_domain/src/selection.rs` `#[cfg(test)]`:

- `explicit_known_and_unknown_are_preserved_without_defaults`: an explicit
  `Unknown` stays unknown even when the profile declares a default; accessors
  return the exact profile and every declared dimension.
- `dimension_invariants_are_enforced`: missing, duplicate, undeclared dimension
  and undeclared known value each return their exact error.
- `policy_profile_set_must_match_exactly`: exact set accepted; missing and extra
  profiles return `ProfileSetMismatch`; the same profile ID at a different
  revision returns `DuplicateProfile`.
- `invalid_declaration_is_rejected_before_selection`: the underlying domain still
  validates profile defaults.
