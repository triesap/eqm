## S019-A — validated policy selection provenance inputs

**Scope:** DEV-006 S019 policy/profile carrier decision.
**Commit SHA:** `5b1a12d87aed0ac56b3389fbc16612c6d9646dd0` (Codex backfill).

Adds `crates/eqm_domain/src/selection.rs` with two fallible, private-field
carriers and exports them from `eqm_domain`:

- `SelectedDimensionStateV2` is explicit `Known(SymbolicValueId)` or `Unknown`.
- `SelectedProfileInputV2<'a>` retains the exact selected `Profile` definition
  plus every declared dimension with its explicit state. Construction rejects
  an undeclared dimension, a repeated dimension, a `Known` value outside the
  dimension's finite declaration, and a profile whose declared dimensions are
  not all present. A missing dimension is an error, not `Unknown`, and no
  development default is applied.
- `PolicySelectionInputV2<'a>` retains the exact selected `Policy` definition and
  the selected profile carriers. Construction rejects a duplicate profile ID
  (including the same ID at different revisions) and any selected profile-ID set
  that is not exactly the policy's required profile-ID set.

These carriers prove structural selection validity only. They confer no
protected authority, trusted execution, freshness or waiver standing, and the
engine selection algorithm is unchanged. `Vec` inputs are used where duplicates
must be rejected before map collection.

  return the exact profile and every declared dimension.

- `policy_profile_set_must_match_exactly`: exact set accepted; missing and extra

- `invalid_declaration_is_rejected_before_selection`: the underlying domain still

**Scope:** DEV-006 contract-projection decision.

Adds `crates/eqm_manifest/src/canonical/contract_v2.rs` with
`CanonicalContractV2` (immutable JCS bytes plus typed `ContractDigest`),
`contract_v2(&FinalizedWorkspaceGraph)` and
`canonicalize_contract_v2`. The root is exactly `capabilities`, `journeys`,
`surfaces`, `fragments` and `extensions`; targets, bindings, policies, profiles,
runners, waivers, imports and adapter locks are excluded.

Explicit v2 entity projections include every canonical capability/journey/

duplicates. A journey's declared surfaces and extension arrays keep their order.
No v1 bytes, schema marker or published schema family changed, and no
manifest-to-engine/protocol dependency was added.

Correction of a prior claim: the domain's `Applicability::all`/`any` constructors
store children in a `BTreeSet`, i.e. they canonicalize child order before the
projection runs. The projection therefore preserves that canonical order and
does not re-sort; it cannot and does not observe a reversed authored order. The
S018-R2 report's wording about "reversing ordered all/any children" was imprecise
about where the ordering is fixed; this is recorded as a self-review note for
Codex. Journey surfaces are a `Vec` in the domain and remain genuinely ordered.

## S019-C — selected-policy/profile projection and same-session assembly

**Scope:** DEV-006 policy/profile projection, crate ownership and application
assembly decision. **Commit SHA:** `1512c9fa7e886781bdf2976dfaabde1d8328ac43` (Codex backfill).

Manifest (`crates/eqm_manifest/src/canonical/policy_v2.rs`) adds
`CanonicalPolicySelectionV2` (immutable JCS bytes plus typed
`PolicySelectionDigest`), `policy_selection_v2(&PolicySelectionInputV2)` and
`canonicalize_policy_selection_v2`. The root is exactly `policy` and `profiles`:

- `policy` is the complete selected policy definition with v2 forms:
  id/revision/title/description/owners, profile IDs, required targets, rule
  selectors and constraints, waiver policy and semantic extensions. All
  populated rule-selector axes are preserved distinctly from absent axes, and
  rule records are a canonical set.
- `profiles` is a canonical set of `{definition, values}` records. `definition`
  is the complete selected profile definition (id/revision/title/description/
  owners, dimension declarations with finite value sets, defaults as an object
  map, extensions). `values` is a canonical set with one
  `{"dimension","state","value"?}` record per declared dimension; `unknown`
  carries no `value` and never becomes a default or an omission.

Application (`crates/eqm_application/src/provenance.rs`) adds
`PolicyProvenanceV2` and `prepare_policy_provenance(session, mode, explicit,
development_default)`. It runs the existing engine `select_policy_profiles`
against the same session's finalized graph, resolves each exact selected profile
definition from that same graph, builds the validated domain carrier and
canonicalizes both identities. It never reselects a latest revision, reloads
files, reads the clock, executes tools, accepts an unrelated preselected graph,
or falls back to the aggregate workspace digest. Missing exact definitions and
invalid selections return typed `PolicyProvenanceError` causes.

Crate direction is preserved: `eqm_engine` gains no serialization dependency and
`eqm_manifest` gains no engine/protocol edge. The workspace digest stays an
aggregate context axis and v1 transport records are unchanged.

## Corrective checkpoint S019-R1 — canonical applicability sets (DEV-007 RF27)

already stores `all`/`any` children in a `BTreeSet` and rejects duplicate
operands, so they are unordered semantic sets. The two separate v2 projections
(binding/exposure and contract/requirement) previously emitted the children in
derived Rust enum order, which is not the wire order. This checkpoint:

- extracts one shared pure `applicability_v2` helper in
  `crates/eqm_manifest/src/canonical/support.rs`, so both public projections use
  the identical recursive logic;
- orders `all`/`any` children by complete JCS member bytes with
  `canonical_set`, rejecting projected duplicates, while `not` remains a single
  child and `membership` values remain a canonical string set;
- keeps journey surfaces and extension arrays ordered, and changes no v1 bytes,
  schema, dependency or domain representation;
- corrects the binding/contract module documentation and the S017/S018/S019
  ordered-`all`/`any` claims.
