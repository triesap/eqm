## S019-A — validated policy selection provenance inputs

**Scope:** DEV-006 S019 policy/profile carrier decision.
**Commit SHA:** recorded externally; backfilled by the next update.

Adds `crates/eqm_domain/src/selection.rs` with two fallible, private-field
carriers and exports them from `eqm_domain`:

- `SelectedDimensionStateV2` is explicit `Known(SymbolicValueId)` or `Unknown`.
- `SelectedProfileInputV2<'a>` retains the exact selected `Profile` definition
  plus every declared dimension with its explicit state. Construction rejects
  an undeclared dimension, a repeated dimension, a `Known` value outside the
  dimension's finite declaration, and a profile whose declared dimensions are
  not all present. A missing dimension is an error, not `Unknown`, and no
  development default is applied.
- `PolicySelectionInputV2<'a>` retains the exact selected `Policy` definition and
  the selected profile carriers. Construction rejects a duplicate profile ID
  (including the same ID at different revisions) and any selected profile-ID set
  that is not exactly the policy's required profile-ID set.

These carriers prove structural selection validity only. They confer no
protected authority, trusted execution, freshness or waiver standing, and the
engine selection algorithm is unchanged. `Vec` inputs are used where duplicates
must be rejected before map collection.

### Tests added

`crates/eqm_domain/src/selection.rs` `#[cfg(test)]`:

- `explicit_known_and_unknown_are_preserved_without_defaults`: an explicit
  `Unknown` stays unknown even when the profile declares a default; accessors
  return the exact profile and every declared dimension.
- `dimension_invariants_are_enforced`: missing, duplicate, undeclared dimension
  and undeclared known value each return their exact error.
- `policy_profile_set_must_match_exactly`: exact set accepted; missing and extra
  profiles return `ProfileSetMismatch`; the same profile ID at a different
  revision returns `DuplicateProfile`.
- `invalid_declaration_is_rejected_before_selection`: the underlying domain still
  validates profile defaults.

## S019-B — exact v2 contract authority

**Scope:** DEV-006 contract-projection decision.
**Commit SHA:** recorded externally; backfilled by the next update.

Adds `crates/eqm_manifest/src/canonical/contract_v2.rs` with
`CanonicalContractV2` (immutable JCS bytes plus typed `ContractDigest`),
`contract_v2(&FinalizedWorkspaceGraph)` and
`canonicalize_contract_v2`. The root is exactly `capabilities`, `journeys`,
`surfaces`, `fragments` and `extensions`; targets, bindings, policies, profiles,
runners, waivers, imports and adapter locks are excluded.

Explicit v2 entity projections include every canonical capability/journey/
surface/fragment field plus nested requirement, fragment-origin and transition
fields, owners, descriptions and semantic extensions. Revisions use the v2 wire
form; extension values use the recursive S018-R1 `{type,value}` representation;
only `dev.equivalencematrix.display` is excluded. Canonical sets (four entity
arrays, owners, requirement records, facets, fragment-origin records, transition
edges, membership values) are ordered by complete member bytes and reject exact
duplicates. A journey's declared surfaces and extension arrays keep their order.
No v1 bytes, schema marker or published schema family changed, and no
manifest-to-engine/protocol dependency was added.

Correction of a prior claim: the domain's `Applicability::all`/`any` constructors
store children in a `BTreeSet`, i.e. they canonicalize child order before the
projection runs. The projection therefore preserves that canonical order and
does not re-sort; it cannot and does not observe a reversed authored order. The
S018-R2 report's wording about "reversing ordered all/any children" was imprecise
about where the ordering is fixed; this is recorded as a self-review note for
Codex. Journey surfaces are a `Vec` in the domain and remain genuinely ordered.

### Tests added (`crates/eqm_manifest/tests/contract_v2.rs`)

- `literal_contract_bytes_and_digest_match_independent_oracle`: a reviewed
  1,935-byte literal projection with `sha256:d36523b4...e2fd6f14`, independently
  recomputed from the bytes as `sha256("eqm:v2:contract" || 0x00 || bytes)`.
- `contract_identity_is_the_typed_domain_wrapper`: the API returns
  `ContractDigest`, equal to `ContractDigest::hash_content(bytes)`.
- `projection_root_has_exactly_the_contract_components`: exact root keys and
  excluded components.
- `semantic_graph_extensions_change_contract_and_display_does_not`: a normative
  graph extension changes the digest; `dev.equivalencematrix.display` does not.
- `entity_extension_change_alters_contract`: a capability extension changes it.
- `ordered_journey_surfaces_are_not_sorted`: reversing declared surfaces changes
  the digest (and is not sorted).
- `applicability_children_follow_domain_canonical_order`: a permutation of
  `all` children is equal (domain canonicalization); a semantic child change
  differs.
- `canonical_requirement_set_order_is_irrelevant`: requirement input order does
  not change the projection.
- `contract_extension_integer_and_text_never_collide`: same-digit integer/text
  graph extensions have distinct bytes and digests.
