### RF21 — P2: NFC-only acceptance bypasses typed syntax and bounds

`v2.rs:484` validates NFC only. Evidence target/unit/requirements/facets and
profile strings use that helper; profile revision lacks the positive Revision
check. `canonical_collections.rs:195` asserts `unit = "café"` is accepted, although
UnitId's existing grammar rejects it. SelectorText also imposes nonempty/length/
control-character constraints, and reviewer uses OwnerRef. Substituting an NFC
predicate for these contracts permits invalid authored metadata and encodes an
incorrect positive control. This is an incomplete v2 allocation, not a claim
that S016 newly weakened v1 readers.

**Repair:** S016-R1 reuses the appropriate domain constructors. Move the Unicode
positive control to valid Unicode-capable metadata; use valid typed IDs elsewhere.
EvidenceSelectorV2Dto::validate currently has no owning v2 consumer. Strengthen
its typed contract but do not claim root integration: that integration stays with
the first step introducing an actual owning v2 selector ingress.
