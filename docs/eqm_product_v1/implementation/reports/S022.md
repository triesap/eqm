## What was implemented

`crates/eqm_application/src/source.rs` (new) centralizes identity acquisition:

- `normalize_repository_identity(&str) -> Result<RepositoryIdentity, SourceProvenanceError>`
  deliberately maps the supported `origin` encodings to one canonical HTTPS
  identity: `git@host:path`, `ssh://git@host/path` and `https://host/path`,
  each optionally with a trailing `.git` and/or `/`. Empty (`MissingRemote`) and
  other encodings such as `git://` (`UnsupportedRemote`) are errors, and the
  normalized value must still satisfy the existing `RepositoryIdentity` grammar.
- `SourceProvenance { repository, source_commit, dirty }` with `clean()` and
  `dirty()`; `inspect_source_provenance(root)` reads the `origin` remote, the
  exact `HEAD` commit and `git status --porcelain --untracked-files=normal`.
- `repository_identity(root)` for identity-only callers.

The duplicated normalization bodies in `eqm_cli` `discover`, `attest`, `verify`
and `release_check` now delegate to the shared application function; the
`release_check` gate reads repository/commit through `SourceProvenance`. No
authority-behavior or wire-representation change was made.

Tests in `eqm_application/src/source.rs`: supported encoding convergence,
unsupported/missing remote errors, clean-tree vs modified-tracked vs
untracked-content labeling, and missing-repository errors. The two existing
release/verify CLI suites still pass unchanged.

## Why this step is not complete

S022's required test states that "modified/untracked fixture content ... cannot
satisfy clean release provenance". Wiring `SourceProvenance::clean()` into the
release gate (`release_check.rs::context_complete`) was implemented, and it
broke the approved CLI test
`commands::release_check::tests::parsed_release_cli_exercises_pass_fail_and_unknown_with_exact_inputs`:
the approved signup release fixture (`tests/fixtures/signup`) writes the
generated release record and runtime facts **after** its single commit, into
untracked `releases/*.generated.json` and `.eqm/` paths, with no `.gitignore`
(e.g. `release_fixture` in `crates/eqm_cli/src/commands/release_check.rs`). The
observed result was `result.status = "unknown"` for the `pass` case. The gate
change was therefore reverted; the dirty flag remains exposed but unconsumed.

The governing text does not specify which paths count as "source" for a clean
release claim, nor where a dirty/untracked marker is represented (a new
evidence-subject wire field, a distinct source identity, or a refusal). Adding a
fixture `.gitignore` would change the fixture's workspace digest and the
`tests/fixtures/signup/goldens/*` oracles, so it was not done.

## Decision request to Codex (smallest options)

1. **Application-only exposure (no gate):** accept `SourceProvenance` as the
   exposed dirty/clean identity for local development and defer the release/
   evidence gate to a later owning step. S022's release-provenance test would
   then be reclassified to that step.
2. **Gate on whole-tree cleanliness:** require `clean()` in release provenance
   and update the signup fixture (commit or ignore its generated records) and
   regenerate the affected goldens as part of this step.
3. **Gate on declared source roots:** define dirty over the `eqm.toml` source
   globs and target roots only, so untracked generated outputs (`.eqm/`,
   generated release records) do not count.

Affected dependencies: S023 and the ordered successors all depend on S022.

## Completion checkpoint S022 — conservative source gate and fixture integration (DEV-008)

**Scope:** DEV-008 S022 — conservative repository-wide source inspection, the

**Resulting commit SHA:** recorded in the external receipt / next ledger update.

### Conservative inspection representation

`crates/eqm_application/src/source.rs` `inspect_source_provenance` now performs a
repository-wide inspection for the explicit repository root:

- `git ls-files -v -z` is parsed and any assume-unchanged (lowercase tag) or
  skip-worktree (`S`) tracked entry returns the typed
  `SourceProvenanceError::ConcealedIndex`; normal status cannot authorize a clean
  claim when the index conceals modified bytes.
- `git status --porcelain=v1 -z --untracked-files=all --ignored=matching
  --ignore-submodules=none` is parsed NUL-delimited, so newlines and spaces in
  paths cannot be misread, and staged, unstaged, deleted, untracked, ignored and
  submodule changes are all included.
- Only untracked (`??`) or ignored (`!!`) content below the reserved generated
  `.eqm/` tree is neutral. Tracked changes remain dirty even inside `.eqm/`.
  Ignored or untracked content elsewhere (including `.eqm-other`-style prefixes)
  is conservatively dirty. `.gitignore` cannot conceal source.
- Missing origin, unsupported identity, invalid commit, unavailable/failed Git
  and concealed entries are typed errors and never default to clean. `Error::source`
  retains the identity/commit causes where available.

`SourceProvenance::clean()` now documents exactly what it means: the defined
inspection observed no non-authorizing content. It is not a claim of byte equality
with `HEAD` and not proof of what executed; races and actual execution binding
remain with the later prepared-source/subject and acquisition steps.

### Release completeness gate

`release_check.rs` now consumes `provenance.clean()` in `context_complete`. A
dirty or failed inspection cannot produce `pass` or `conditional`; successful
underlying tests do not override this. No v1 wire field was added and signed
originals are not reinterpreted. Attest/verify were not changed to fabricate a
clean executed-subject claim.

### Fixture repair (reserved output tree)

The signup fixture now writes generated release, runtime-facts and evidence
records below the reserved `.eqm/` tree, and ships a fixture `.gitignore`
(`.eqm/`, `generated/`) that is copied and committed before the fixture's initial
commit. `release_fixture`, `release_invocation`, the release-record ingress test
and the renderer public-command case were moved atomically to
`.eqm/releases/<name>.generated.json`. The fixture also tracks `.eqm/tracked.json`
so the "tracked change inside the output tree" control is constructible. No broad
ignore patterns were added; generated artifacts are not committed as source.

A changed fixture source commit from this setup is handled by the existing dynamic
subject construction, not hardcoded as production provenance.
