Purpose and exact behavior changed:
`WorkspaceGraph::new` previously indexed participation by authority ID only,
allowing two distinct rule IDs to constrain the same `(requirement, target)`
coordinate; `evaluate_participation` then selected whichever rule iterated
first. Graph construction now routes through the existing
`validate_participation_rules` check and returns the typed stable
`DuplicateParticipationCoordinate` (or `DuplicateParticipation` for a repeated
ID). The public evaluation boundary explicitly rejects a registry where more than
one rule matches the evaluated coordinate (`AmbiguousParticipation`) instead of
selecting a winner. Exact true/false/unknown behavior, disjoint coordinates and
profile-unknown cases are preserved; no global inclusion, exclusion or waiver is
introduced. The independent `eqm:v2:participation` projection and
`ParticipationDigest` are implemented over exactly
`id`/`requirement`/`targets`/`applicability`/`extensions` and reused by the v2
graph identity, leaving the frozen `ContractDigest` membership unchanged.

Spec/API/schema/DB/authority impact: additive typed domain digest and two typed
error variants; no wire/schema change and no dependency change.
