Purpose and exact behavior changed:
The authored `SubjectManifestV2Dto` `id` is now validated as an exact symbolic
`SelectorText` identity rather than its own SHA seal, matching the domain model;
the digest is computed separately as `SubjectManifestDigest` over the canonical
root `id`/`revision`/`entries` with only the transport `schema` excluded. Strict
validation now rejects both exact and logical (same occurrence key) duplicates
before any promotion. A bytes-first `CheckedSubjectManifestV2` retains the raw
bytes, the canonical semantic bytes and the typed digest, and mutable DTOs are
rebound through `checked`, which reparses and rejects a mismatch.

Matching compares all and only the expected scenario occurrences against
independently supplied immutable `ExpectedSubjectAxis` values (repository,
commit, source-content, typed target/provider configuration, build and artifact).
Every supplied axis must match; missing, extra and target/provider kind
substitution reject. `SubjectMatchMode::Development` admits only explicitly
declared absent axes, while `Completeness` rejects any absent axis. The typed
target configuration comes from the independent expected authority, never from
relabeling the untrusted wire digest string, so no trust, source or build
verification is claimed. Existing entry field names and omitted absence are
preserved; provider typing extends at S040.

Spec/API/schema/DB/authority impact:
Additive protocol API; no schema bytes changed (the `id` constraint is runtime
only), no dependency change, and no v1 behavior change.
