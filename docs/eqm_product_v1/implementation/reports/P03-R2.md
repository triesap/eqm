Purpose and exact behavior changed:
The complete v2 semantic-graph projection no longer collapses distinct sum-type
inputs to identical bytes. Runner arguments now project as the approved tagged
records: a literal is `{"kind":"literal","value":<exact text>}` and the
substitution templates are `{"kind":"target_root"}`, `{"kind":"selector_json"}`
and `{"kind":"result_path"}`. Working directories project as
`{"kind":"target_root"}`, `{"kind":"repository","path":<path>}` or
`{"kind":"result_path"}`, so a repository path that merely looks like a
placeholder (for example `{target_root}`) is distinct from the expanded
template. Argument order is preserved. Waiver scope subjects project with the
existing approved tagged v2 scope forms: `{"kind":"target","target":...}`,
`{"kind":"provider","provider":...}` and
`{"kind":"target_set","targets":[...]}`, so a target, provider and target set
never share identity. The v1 projection bytes, the frozen S019 contract
projection, and all unrelated component identities are unchanged.

Spec/API/schema/DB/authority impact:
No wire-version, schema, dependency or v1-byte change in this checkpoint. The v2
projection gains the same lossless representation already used by the runner
identity, without a manifest→runner or domain/engine serialization dependency.
The still-placeholder v2 semantic-graph schema is intentionally not relaxed or
extended here; P03-R3 replaces it with real typed member schemas atomically.
