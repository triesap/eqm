Purpose and exact behavior changed:
The manifest authority key for a policy or profile was `policy:{id}` /
`profile:{id}` without the revision, so two authored revisions for one ID
collided as `DuplicateAuthority` and only one could load. The key now includes
the exact revision (`policy:{id}@{revision}` / `profile:{id}@{revision}`), so
distinct revisions load while a duplicate definition of the same exact revision
still rejects. The CLI accepts a new `--policy <ID[@REVISION]>` global option and
an optional `id@revision` prefix in `--profile`; the adapter resolves the exact
policy and each exact profile revision, and errors on an ambiguous or missing
stored authority instead of choosing a latest revision. No selection rule, wire
member, generated schema byte, dependency or `Cargo.lock` entry changed.
