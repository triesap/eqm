## Scope

DEV-005 replaces the ID-only binding-digest shortcut with a separate complete v2
binding projection. `crates/eqm_manifest/src/canonical/binding_v2.rs` adds
`binding_v2(&Binding) -> Result<Value, CanonicalizationError>`,
`canonicalize_binding_v2(&Binding) -> Result<CanonicalBindingV2, ...>` and the
`CanonicalBindingV2 { bytes, digest }` value, using the existing
`DigestDomain::Binding` (`BindingDigest`) domain.

The existing v1 `binding`/`fragment`/`graph` projections, APIs, bytes and hashes
are unchanged. The v1 graph literal vectors in `canonical.rs` still pass. No new
digest domain, dependency or `eqm_manifest` -> `eqm_protocol` edge was added.

## Behavior

- Include every existing binding semantic field: id, revision, target, unit,
  owners, artifacts (role/path/surface/symbol/selector), exposures
  (surface/state/applicability/route), evidence specifications (kind,
  requirements, facets, runner, selector, minimum count, freshness) and
  extensions at binding, artifact, exposure and evidence-spec level.
- Encode revisions, `minimum_count`, `freshness` and extension integers with the
  approved v2 integer wire forms: an exact JSON integer within
  `|n| <= 2^53-1`, otherwise a canonical decimal string.
- Order owners, artifacts, exposures, evidence specifications, requirements,
  facets and applicability membership values by each member's complete canonical
  JSON UTF-8 bytes, and reject exact duplicate members rather than silently
  erasing them (defensive; existing typed construction already prevents
  duplicates).
- Preserve the order of ordered extension/expression arrays; do not recursively
  sort every array.
- Exclude only the `dev.equivalencematrix.display` namespace; include every other
  extension namespace. Keep an artifact's declared path (semantics) and never
  invent a binding description/comment field. Comments, whitespace, source spans
  and the manifest's own location remain absent parse provenance.

## Self-review

This is a component projection, not an end-to-end binding identity: later owning
v2 construction/relationship steps must integrate `canonicalize_binding_v2`, and
the v1 transport/runner identities are not reinterpreted here. The projection is
pure and allocates only JSON values; the only new public surface is the
`CanonicalBindingV2` type, the two projection functions and the
`DuplicateMember` error variant. The duplicate-member rejection is defensive and
is not reachable through the typed domain constructors, so it has no dedicated
public-ingress negative test; it is exercised only by construction safety.
`cargo xtask verify`, Linux, signing and live product acceptance were not run.

## Corrective checkpoint S018-R1 — typed identities and extension type tags

**Scope:** DEV-006 RF24/RF26, shared with S018.

- `CanonicalBindingV2` now stores and returns the existing `BindingDigest`
  wrapper, constructed with `BindingDigest::hash_content(&bytes)`. This is a
  wrapper-only change: bytes and digest text are unchanged, and raw extraction
  is only through `as_digest` at a wire/legacy boundary.
- `extension_value_v2` now recursively encodes every `ExtensionValue` as an
  object with exactly `type` and `value` (`boolean`, `integer`, `string`,
  `array`, `object`), preventing an out-of-safe-range `Integer` from colliding
  with a digit-containing `String` (and an authored tag-like object from
  colliding with the typed value it resembles). Ordered extension arrays keep
  their order; object payloads are JCS-keyed; the extensions namespace map stays
  a map and only `dev.equivalencematrix.display` is excluded.
- Tests added: `binding_identity_is_the_typed_domain_wrapper`,
  `extension_integer_and_text_with_same_digits_never_collide` (positive and
  negative out-of-safe-range, nested arrays/objects, tag-like object) and
  `extension_encoding_is_recursive_for_every_variant`. `BOUNDARY_*` and the
  ordered-array assertions were updated for the approved representation only.
