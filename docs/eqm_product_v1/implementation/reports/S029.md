## Scope

DEV-009 allocates shared implementation input as an authored source-component
authority with confined canonical roots, owners, explicit component-ID
dependencies and semantic extensions. Targets reference components by ID; exact
source content stays a separate subject axis, and no default shared-source
authority exists.

## Representation

- `crates/eqm_domain/src/id.rs` adds `SourceComponentId` through the existing
  validated identifier family (two or more lowercase/underscore/digit segments).
- `crates/eqm_domain/src/entity.rs` adds `SourceComponent` with `id`, `roots`,
  `owners`, `dependencies`, `extensions`. Its constructor requires at least one
  confined root and one owner and rejects duplicate roots, duplicate owners, a
  self-dependency and duplicate dependencies. The exact root set is validated as
  repository-relative `RepoPath` values.
- `Target` gains explicit `source_components` and `depends_on` ID sets through
  `with_source_components`/`with_depends_on` (duplicates rejected) with read
  accessors. `Target::new` keeps its signature and leaves both sets empty.
- `crates/eqm_domain/src/graph.rs` adds `validate_source_components`, which
  indexes one supplied registry and rejects duplicate authority and dependencies
  absent from that same registry. Transitive ownership and cycles remain the
  engine's graph-resolution responsibility (S030).
- `crates/eqm_manifest/src/canonical/target_v2.rs` projects canonical
  `source_components` and `depends_on` ID sets only when nonempty, so a target
  that models no shared source keeps its previous six-member identity. The v1
  `target()` projection is unchanged; the workspace reader/DTO lands at
  S031/S032 under the DEV-009 allocation.

## What this does not prove

This models shared source components and target-to-component/dependency
references at the domain layer and in the target v2 projection. It does not load
them from authored workspace manifests, resolve transitive ownership or
dependency cycles, or verify any source content or build artifact. No `cargo
xtask verify`, Linux, coverage/mutation/fuzz/bench, release packaging or signing
lane was run. S029 is complete pending Codex acceptance; S030 follows.
