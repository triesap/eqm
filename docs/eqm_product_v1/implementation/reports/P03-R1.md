Purpose and exact behavior changed:
Production preparation no longer calls the v1 graph projection unconditionally.
The loader records the exact authored workspace schema version, and
`prepare` selects the matching representation: a genuine v1 workspace projects
under the frozen `eqm:v1:semantic-graph` domain, while an authored v2 workspace
projects under the complete `eqm:v2:semantic-graph` identity and stores that
digest as the aggregate `workspace_digest`. The v2 root keeps the existing graph
collection names and adds `source_components` and `participation`; targets use
the complete v2 target projection (role/source_components/depends_on), and
capabilities/journeys/surfaces/fragments, bindings, policies, profiles, runners,
waivers, imports and adapters use the approved v2 integer, set-ordering,
omission and type-tagged extension forms. The v1 projection now rejects any
v2-only metadata/authority (`CanonicalizationError::V2OnlyMetadata`) instead of
silently omitting it. `PreparedSession::semantic_graph_version` and
`semantic_graph_domain` expose the chosen version/domain so the aggregate SHA
cannot be mistaken for a v1 identity.

Spec/API/schema/DB/authority impact:
Additive domain digest identity and a new generated v2 semantic-graph schema
under the already coordinated v2 protocol namespace. No v1 schema, bytes or
digest changed. `LoadedWorkspace` gains an `authored_version` accessor and
`PreparedSession` gains version/domain accessors. No domain/engine serialization
back-edge; the projection stays in `eqm_manifest`.
