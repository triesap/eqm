## Scope

S024 adds validated execution-lineage identifiers and explicit, complete
relationships, and rejects missing or inconsistent lineage instead of deriving it
from timestamps, file counts or directory ordering. It is additive domain
modeling: no storage, no wire field, no trust promotion and no evaluation change.

## Identifiers

`crates/eqm_domain/src/id.rs` adds five validated identifiers using the existing
`define_id!` grammar: `PlanId`, `CampaignId`, `RunId`, `LogicalCaseId` and
`AttemptId`. They are exported from `eqm_domain`.

## Relationships

`crates/eqm_domain/src/evidence_result.rs` adds:

- `EvidenceLineageParts` — the optional lineage fields as received.
- `EvidenceLineage` — a complete plan → campaign → run → logical case → attempt
  lineage. `from_parts` rejects a missing plan, campaign, run, logical case or
  attempt with its exact typed error; nothing is derived from timestamps.
- `EvidenceExecution` — one run/logical-case execution with uniquely named
  attempts. Construction rejects an empty attempt list
  (`AttemptsRequired`) and repeated attempt names (`DuplicateAttemptId`);
  distinct runs/cases remain independent records.

New typed errors: `MissingPlan`, `MissingCampaign`, `MissingRun`,
`MissingLogicalCase`, `MissingAttempt`, `AttemptsRequired`, `DuplicateAttemptId`.

## Tests added and what each proves

`crates/eqm_domain/src/evidence_result.rs`:

- `missing_lineage_parts_are_rejected_not_derived`: a complete lineage is
  accepted; dropping the plan returns `MissingPlan` rather than a derived value.
- `duplicate_attempt_names_reject_and_runs_are_independent`: an empty execution
  and a repeated attempt name reject; the same attempt names under a different
  run/case form an independent execution.

## Corrective checkpoint S024-R1 — checked lineage relationships (DEV-009 RF35)

**Scope:** DEV-009 S024-R1 / RF35. **Baseline HEAD:**
`96a20f4bcd5c585abd00210446be82a8d626cd19` (S023-R1; reviewed source `d6261c4`).
**Resulting commit SHA:** recorded in the next ledger update (no self-reference).
**Commit subject:** `fix: validate explicit execution lineage relationships`.

RF35 observed that typed identifiers, presence and duplicate-attempt
construction were retained, but no operation matched a lineage's
plan/campaign/run/case/attempt against a declared execution and an independently
supplied expected context. This checkpoint adds that validation.

### Representation

`crates/eqm_domain/src/evidence_result.rs`:

- `ExpectedLineageAuthority` holds the explicit expected plan and campaign. It is
  independent supplied context; the lineage/execution constructors, producer
  strings and presence never establish it. `new`, `plan()` and `campaign()`
  are read-only.
- `EvidenceLineage::validate_against(&self, execution, expected)` requires:
  exact plan and campaign against the expected authority; exact run and logical
  case against the declared execution; and the attempt to be a declared member
  of that execution. Each failure returns its own typed error and nothing is
  derived from timestamps or directory ordering.
- New typed errors: `PlanMismatch`, `CampaignMismatch`, `RunMismatch`,
  `LogicalCaseMismatch`, `AttemptNotDeclared`.

No storage, wire field, schema or trust promotion was added. `EvidenceLineage`
and `EvidenceExecution` remain internal records built only through their fallible
constructors.

### Tests added and corrected

`crates/eqm_domain/src/evidence_result.rs`:

- `missing_lineage_parts_are_rejected_not_derived` now drops each of the five
  parts separately and asserts `MissingPlan`, `MissingCampaign`, `MissingRun`,
  `MissingLogicalCase` and `MissingAttempt` respectively.
- `validate_against_declared_execution_and_expected_authority`: a matching
  lineage is accepted; wrong expected plan, wrong expected campaign, wrong run,
  wrong logical case and an undeclared attempt each return their own typed error.
- `run_and_case_axes_are_independent`: holding all else equal, a different case
  rejects only on `LogicalCaseMismatch` and a different run rejects only on
  `RunMismatch`, so the two axes are not collapsed.
- Retained `duplicate_attempt_names_reject_and_runs_are_independent` (empty and
  duplicate attempts) unchanged.
