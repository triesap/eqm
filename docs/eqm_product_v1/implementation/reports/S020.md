separate from selected-policy, source snapshot, build artifact and execution

  `canonicalize_target_configuration_v2(&Target) -> Result<CanonicalTargetConfigurationV2, ...>`

  `prepare_target_configuration(&PreparedSession, &TargetId) -> Result<CanonicalTargetConfigurationV2, TargetConfigurationError>`
  with `TargetConfigurationError::MissingTarget { target }` and

  `Error::source`);

  (`project_target_configuration_v2`, `canonicalize_target_configuration_v2`,
  `CanonicalTargetConfigurationV2`, `prepare_target_configuration`,
  `TargetConfigurationError`).

The projection is pure and adds no `eqm_manifest` -> engine/protocol dependency.
No new domain carrier was needed for the already-valid `Target`.

## Representation

The internal JSON root has exactly `id`, `root`, `platform`, `framework`,
`owners` and `extensions` — no schema URI and no nested `target` wrapper:

```json
{"extensions":{},"framework":"sveltekit","id":"web","owners":["owner://team/web"],"platform":"web","root":"apps/web"}
```

- Strings retain their validated exact values. `root` remains the authored
  `RepoPath`; there is no absolute expansion, filesystem canonicalization or
  case folding.
- `owners` is a complete member-byte canonical set.
- `extensions` uses the recursive DEV-006 `{"type","value"}` tags and excludes
  only `dev.equivalencematrix.display`.
- `canonicalize_target_configuration_v2` enforces the existing
  `MAX_PROJECTION_BYTES` bound and returns the typed `CanonicalizationError`.

### Absence of build/profile/source references

At this step `Target` has ZERO build, profile or source-component reference
fields, so there is nothing to project for them. Their absence is stated here,
in the module documentation and in the root-key test; it is **not** encoded as
`null`, an invented empty collection, a successful verification or an invented
`"none"` authority. `TargetConfigurationDigest` is a target-definition identity
only: it does not establish a selected policy/profile (bound separately by
`PolicySelectionDigest`), a source revision, resolved source-component content or
a build artifact digest.

### Later closure obligations (retained)

When S028 adds role and S029–S032 add source-component relations, the target
projection must be updated **in the same owning step** to bind every newly
available normative target field (a role uses its exact validated ID; source-
component references use a canonical set of exact IDs). S031/S038/S043 must
prove that linkage together with their source-schema/subject/negative cases.
This identity must not be silently replaced by a workspace digest.

## Application entry

`prepare_target_configuration` looks up the requested exact `TargetId` in the
session's immutable finalized graph and invokes the pure manifest projection. It
does not reload the graph or files, run selection, read the clock or execute
tools, and it never substitutes an empty/default target or the aggregate
workspace digest. An unavailable target is `MissingTarget` (carrying the
requested ID) with no causal source; projection failures retain their
`CanonicalizationError` through `Error::source`.

`crates/eqm_manifest/tests/target_v2.rs`:

- `literal_target_bytes_and_digest_match_independent_oracle`: exact bytes and
  typed digest with no trailing newline.
- `projection_root_has_exactly_the_current_target_fields`: the six-member root
  and the absence of schema/build/profile/source/workspace-digest fields.
- `target_identity_is_the_typed_domain_wrapper`: the API returns the concrete
  `TargetConfigurationDigest`.
- `same_id_field_and_semantic_extension_mutations_change_identity`: same-ID root,
  platform, framework, owner and semantic-extension changes each alter identity.
- `display_extensions_do_not_change_identity`.
- `owner_permutations_canonicalize`: projected owner order is the member-byte
  order and permutations are identical.
- `extension_integer_and_text_with_same_digits_never_collide` and
  `nested_large_extension_values_remain_distinct`: the recursive tags keep large
  integers distinct from digit strings.

`crates/eqm_application/tests/target_provenance.rs`:

- `exact_target_lookup_returns_typed_identity`: exact `android` lookup returns the
  typed identity and differs from `ios`.
- `missing_target_returns_typed_error_with_requested_id`: typed `MissingTarget`
  with the requested ID and no causal source.
- `unrelated_target_and_policy_changes_leave_this_identity_unchanged`: changing
  the unrelated `ios` framework moves only the `ios` identity; a policy-only
  change moves nothing.
- `authored_formatting_change_does_not_move_target_identity`: adding a comment to
  `eqm.toml` preserves the identity.
- `same_session_lookup_survives_authored_file_mutation`: after an authored
  `eqm.toml` mutation, the prepared session returns the identical identity while
  a fresh preparation observes the mutation.
