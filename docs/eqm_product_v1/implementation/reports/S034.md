## Scope

DEV-009 allocates a domain participation rule that binds one exact
fully-qualified requirement to explicit target IDs and the existing typed
applicability vocabulary, with a unique authority and semantic extensions.
Ambiguous or duplicate authority rejects; unspecified context stays unknown.

## Representation

- `crates/eqm_domain/src/id.rs` adds `ParticipationRuleId` through the existing
  validated identifier family (two or more segments).
- `crates/eqm_domain/src/policy.rs` adds `ParticipationRule` with private fields
  `id`, `requirement`, `targets`, `applicability`, `extensions`. Its constructor
  requires nonempty distinct targets and reuses the existing
  `PolicyBuildError::TargetsRequired`/`DuplicateTarget` failures. Accessors
  return the exact typed members; applicability keeps true/false/unknown
  distinct because it is the existing typed `Applicability`.
- `validate_participation_rules` indexes one supplied registry and rejects a
  duplicate rule authority (`DuplicateRule`) or two rules constraining the same
  `(requirement, target)` coordinate (`DuplicateCoordinate`). It infers no
  target/profile existence and creates no automatic dependency.

This step is domain-only. The v2 `participation` manifest DTO/schema and engine
resolution/evaluation land at S035/S036 under the DEV-009 allocation.
