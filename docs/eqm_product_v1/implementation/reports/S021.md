## Scope

`crates/eqm_runner/src/resolution.rs` previously computed the resolved runner
digest from the semantic `RunnerDefinition` only. For a
`RunnerProgram::Repository` the independently verified executable digest of the
same path was not part of the identity, so replacing executable bytes at the same
path left `ResolvedRunner::digest()` unchanged. `EVIDENCE_AND_IDENTITY.md`
requires a runner identity used in evidence to include the approved executable
content plus its definition and relevant execution/toolchain context.

This step replaces `canonical_runner_digest(definition)` with
`canonical_runner_identity(definition, program, approved_guarantees)`:

- the semantic definition (id, revision, owners, backend, argv templates, cwd,
  environment/secret references, limits, declared guarantees, semantic
  extensions) is encoded as before, with the declared program moved out of the
  definition block;
- the **resolved** program is encoded next, including the independently verified
  digest (`Repository { path, digest }`) or the locked source identity and digest
  (`Locked { resolved, digest }`);
- the approved enforceable backend guarantees for this backend are encoded as
  the relevant approved execution/toolchain context;
- the domain label is now `eqm:v1:runner-identity`.

`ResolvedRunner` stores the approved guarantees and exposes them through
`approved_guarantees()`; `digest()` still returns the concrete `Sha256Digest`
consumed by `eqm_cli`/protocol evidence assembly. A repository executable with no
independently verified digest still returns `ProgramNotAuthorized` and never
becomes executable.

No eqm_protocol type changed; the existing `runner_digest` string field now
carries the stronger identity.

## Tests added and what each proves

`crates/eqm_runner/src/resolution.rs`:

- `executable_replacement_changes_runner_identity`: the same path with different
  verified bytes resolves to a different identity.
- `definition_only_change_invalidates_runner_identity`: a limits-only definition

- `approved_execution_context_changes_runner_identity`: widening the approved

- `equivalent_definitions_resolve_to_one_digest` (retained): owner/environment
  collection order does not change the identity.
- `authority_backend_resource_and_program_mismatches_fail` (retained): the
  unresolved-program and authority failures are unchanged.

## Corrective checkpoint S021-R1 — approved v2 runner identity (DEV-008 RF30)

**Scope:** DEV-008 S021-R1 — replace the invented `eqm:v1:runner-identity`

**Resulting commit SHA:** recorded in the external receipt / next ledger update.
**Commit subject:** `fix: align resolved runner identity with v2 provenance`.

### Representation

`crates/eqm_runner/src/identity.rs` (new) owns a pure, bounded JCS projection
whose root is exactly `definition`, `program`, `approved_guarantees`:

- `definition` projects every `RunnerDefinition` field: id, revision, owners,
  backend, declared program, ordered args, cwd, environment, secret references,
  timeout_ms, max_output_bytes, max_concurrency, declared guarantees and semantic
  extensions. Declared program is `{"kind":"repository","path"}` or
  `{"kind":"locked","resolved","digest"}`.
- `program` is the resolved program: the declared repository form plus the
  independently verified digest, or the locked resolved/digest pair. Resolution
  constructs both from the declaration, so a resolved repository path matches
  its declaration and a locked identity/digest matches exactly.
- `approved_guarantees` is the actual independently supplied enforceable context
  for the backend, not a hypothetical host claim.

Explicit v2 forms replace default/v1 Serde rehashing: args are tagged
`literal`/`target_root`/`selector_json`/`result_path` records; cwd is tagged
`target_root`/`repository`/`result_path`; environment is the complete
`{name,source,value?}` set with `value` present only for a literal source;
secrets are `{name,provider}` references and never values. Owners, environment,
secrets and both guarantee collections are full JCS member-byte canonical sets
with duplicate rejection; args and extension arrays retain order. Counts and
revisions use ADR-0013 integer/string rules. Extensions use the recursive DEV-006
type tags and exclude only `dev.equivalencematrix.display`. Optional absence is
omission. The projection is bounded at the shared 256 MiB component limit and
returns typed errors with no fallback to a definition hash.

`ResolvedRunner` now stores the immutable canonical bytes plus `RunnerDigest`.
`canonical_bytes()` returns the exact bytes and `identity_v2()` returns the typed
`RunnerDigest` (domain `eqm:v2:runner`). `digest()` is documented and retained
only as the legacy/wire adapter returning `identity_v2().as_digest()`; it feeds
the existing `runner_digest` evidence field without adding a v1 wire field.

### Runtime hash change (explicitly approved)

The resolved-runner identity values change: they are now
`SHA256("eqm:v2:runner" || 0x00 || jcs_bytes)` instead of the retired private
`eqm:v1:runner-identity` binary hash. This is expressly approved by DEV-008.
No v1 DTO shape, `schemas/v1/**` byte, or established v1 graph/fragment/
definition oracle changed; the v1 `eqm_manifest::canonical::runner` projection is
untouched.

### Tests added and what each proves

`crates/eqm_runner/src/identity.rs`:

- set permutations (owners/environment) canonicalize; ordered argv is bound and
  not sorted; placeholder literal text differs from template substitution;
  display extensions are excluded while semantic extensions are bound;
  integer/text extensions never collide; full-range quantities emit literal
  decimal-string tokens; locked and repository resolved programs retain their
  form; secret references project without values; approved context changes the
  identity.

`crates/eqm_runner/src/resolution.rs`:

- `literal_v2_runner_identity_bytes_and_digest_match_independent_oracle`: literal
  bytes and typed digest, with the wire adapter equal to the typed digest.
- `actual_executable_replacement_changes_identity_through_acquisition`: creates a
  temp repository executable, reads its actual bytes with `fs::read` and
  `Sha256Digest::hash_content` (the exact pattern used by the CLI repository
  authority builder), resolves, replaces the file bytes on disk, and observes a
  different identity. This is real acquisition, not an authority-map mutation.
- `locked_program_identity_binds_locked_resolution_and_digest`: a container
  `Locked` program resolves to a stable typed identity.
- Retained controls: map-boundary executable replacement, definition-only change,
  approved-context change, canonical owner/environment permutations, and
  unresolved/authority/backend/resource rejection.
- Executed doctests: a `compile_fail` cross-domain proof that a `RunnerDigest`
  cannot be passed where a `TargetConfigurationDigest` is required, plus a
  positive typed construct/compare/as_digest example.
