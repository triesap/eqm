## Scope

DEV-009 allocates an authored, extensible `RoleId` that is independent of the
stable target ID, root, platform, framework and owners. A legacy target carries
typed absence, never an invented role; the target v2 projection adds `role` only
when one is present, and the v1 projection is unchanged.

## Representation

- `crates/eqm_domain/src/id.rs` adds `RoleId` through the existing validated
  identifier family (one or more lowercase/underscore/digit segments). It is a
  symbolic identity, not a three-role enum; no product-specific role list is
  hardcoded.
- `crates/eqm_domain/src/entity.rs`: `Target` gains private `role: Option<RoleId>`.
  `Target::new` keeps its existing signature and sets typed absence; the new
  `Target::with_role` adds an explicit role; `Target::role()` reads it. The target
  ID and every existing field are unchanged.
- `crates/eqm_manifest/src/canonical/target_v2.rs` inserts `role` into the target
  v2 projection only when present. A role-less target projects the same six
  members and the same reviewed literal bytes/digest as before; a role-bearing
  target adds the member and changes `TargetConfigurationDigest`. The v1
  `target()` projection in `crates/eqm_manifest/src/canonical.rs` is unchanged.

No workspace DTO/reader or schema is changed at this step; the manifest reader
gains target role at S031/S032 under the DEV-009 allocation. No participation,
source-component or dependency semantics are introduced.
