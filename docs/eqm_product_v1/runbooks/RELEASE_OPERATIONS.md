# Shadow rollout, release authorization and rollback

## Before enforcement

Record exact protected expectations, evaluator artifact/configuration, required target/provider/scenario scope, supported mixed-version cohorts, signer/verifier authority, exact artifact identities, destination/channel, validity and allowed deviation policy. Run the final supported-host/native/product/security/crypto/storage gates. Assign accountable reviewers/operators.

Use shadow mode first. Compare EQM decisions with independently reviewed expected outcomes for representative passing and deliberately failing cases, including deleted requirements, wrong subjects, missing end-to-end evidence, failed manual review, duplicate attempts, expiry, unverifiable runtime facts and unauthorized waivers. Investigate discrepancies; do not adjust expectations merely to match the code.

## Enforcement activation

An authorized operator explicitly records activation for the exact approved evaluator/authority/configuration and environment. A coding agent may prepare this record but cannot invent approval or perform publication/deployment without permission. Missing product/host/identity evidence means remain shadowed.

## A release

Prepare the candidate subject manifest and approved plan; acquire/import evidence under independent worker authority; freeze inputs; evaluate complete scope; establish current acceptance; optionally sign the decision; request protected authorization. Validate every mandatory verification input. Conditional acceptance needs exact permitted deviations; unknown never authorizes.

The existing deployment integration validates the authorization against actual artifacts, destination/channel and time. A different artifact with the same source commit is not automatically authorized. Transformed artifacts require approved verified provenance or reevaluation. EQM supplies the records/validator, not a new deployment orchestrator.

Post-deployment receipts/observations feed a later conformance evaluation. Do not require impossible future observations in initial readiness or construct circular evidence/decision digests.

## Rollback

On suspected evaluator/trust/store correctness failure, pause promotion or restore the previously reviewed evaluator/authority using tested compatibility/recovery procedures. Preserve current and historical decisions for diagnosis. Never replace verification with producer claims, disable subject checks, auto-waive failures, or map unknown to pass for availability.

## Final records

Record actual decision/input/authorization/deployment references, exact artifacts/configuration, contributing waivers, current-acceptance context, independent review, commands/results and remaining platform gaps. Separate software readiness from operational permission. No part of this runbook grants blanket live signer, publishing, or deployment access.
